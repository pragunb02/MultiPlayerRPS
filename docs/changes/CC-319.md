The browser tests no longer lose a page's stylesheet with `net::ERR_TOO_MANY_RETRIES`, which failed 13 CI runs since 2026-10-18 (main at 3be99e6 among them), a different test each time. The cause was the e2e server's self-signed certificate, not the server: with only `ignoreHTTPSErrors`, Chromium fails each new connection with a certificate error and then restarts the request, a certificate error on one connection attempt restarts every request waiting for it, and Chromium gives up after 32 restarts of one request. The page's first stylesheet waits longest, so on a busy runner it passed 32. Chromium's network log of our own runs showed 18 to 31% of requests restarted before (up to 5 times on a laptop, always a `<head>` stylesheet) and none after. Chromium in the browser tests now starts with `--ignore-certificate-errors`, which accepts the run's certificate during the handshake and trusts no more than `ignoreHTTPSErrors` already did. Keep-alive timers, HTTP/2, the rate limits, the static handler and restarts were checked and ruled out. Players are not affected: Render's edge presents a publicly trusted certificate, so a real browser never restarts a request this way. The app does not change.
