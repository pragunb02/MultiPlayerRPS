Shaped for spec review (decision-first, CC-311), answered by the owner ("Accept all", 2026-10-20) and built behind
the `telemetry_ingest` flag, off: `POST /api/telemetry` answers 204 whatever it kept, drops a batch with GPC or DNT,
from a console admin, from a known bot or while the flag is off before reading it, takes at most 8 KB, 30 events and
600 batches per 10 minutes per session (per network for a visitor) and 2 000 events per network a day, checks each event against the shared catalogue
(`packages/shared/src/telemetry/events.js`) and drops only the invalid ones, counts at most 100 000 events per India
day into hourly counters (a new `telemetry_counts` collection, one counter per tuple of catalogue fields and India hour,
never a single event, its order or its batch), kept 30 days by a TTL index and with no id of anyone, counts what it dropped in Grafana as `telemetry.dropped` by
reason, records the server's own sign-up, login, logout, new guest and server error counts through the same rules,
and gives the owner a purge (`DELETE /api/admin/telemetry?before=`). `text/plain` is allowed on this route only, for
`sendBeacon`. While the privacy switch is off, the web app's `X-CC-Counts: off` header stops the server's own events too.
