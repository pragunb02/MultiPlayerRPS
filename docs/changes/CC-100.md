A heading or dialog that the app focuses in code, so a screen reader starts there, no longer draws a large focus
ring on page load or after a click, and now draws it for keyboard players in every browser. Chromium counted a
focus made on load as keyboard focus, so the invite chooser's heading showed a ring before any press; the
challenge page and the pass-and-play hand-over hid it even from keyboard players. One shared rule replaces the
three screens' own: `app/inputModality.js` marks the page while the keyboard is in use and `global.css` rings a
`tabindex="-1"` target only then. The design contract says how to do it.
