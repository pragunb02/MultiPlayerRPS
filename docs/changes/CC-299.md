Changelog fragments: each pull request adds `docs/changes/CC-###.md` (front matter with the ticket, date, type, board status and ADRs, then this line, optionally a board row) instead of editing PROGRESS.md and BACKLOG.md. The coordinator runs `node scripts/bin/collect-changes.mjs` on a fresh main, which folds the fragments into the changelog newest first, sets each board row's status and links, formats both files and deletes the fragments; a second run changes nothing, `--check` writes nothing. A new CI job, `Changelog fragments`, checks every fragment and fails a pull request that edits PROGRESS.md's changelog by hand, unless each new line comes from a fragment the same pull request deletes (the collector's own pull request). The coordinator assigns ticket and ADR numbers at dispatch; builders never edit the next free lines (CLAUDE.md).
