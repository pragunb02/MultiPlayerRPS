A player can no longer have more than 3 challenges open, or send two challenges to one person less than ten minutes
apart, by making them in the same millisecond. Both rules used to be decided by sorting the sender's challenges by
time after the new one was stored. Challenges from the same millisecond were then ordered only by their random ids,
so a fourth could count as one of the first three, and a second to the same person as the first. Each open
challenge now holds one of its sender's three places, and each challenge to a person holds a ten-minute mark. A
unique index lets only one challenge hold each place and each mark, so both rules hold in one write. Challenges
stored before the change are still counted from the stored list. A new integration test on MongoDB made 4 open
challenges and 2 to the same person before the fix, and makes 3 and 1 now.
