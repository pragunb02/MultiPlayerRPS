Full UI and UX audit of the web app, as a baseline before any redesign: `docs/design/AUDIT-2026-10.md`, docs only, no app change. 77 states (visitor, guest, account and owner; every page, game, dialog, popup, empty and error state) were captured at 390, 768 and 1280 px in light and dark, giving 451 screenshots on `pr-evidence/audit-2026-10/`. Each state was checked with axe, for overflow, tap targets, reduced motion and type sizes, with keyboard and hover checks on the key states. The audit adds the bundle sizes, Lighthouse mobile and a static read of the CSS. It gives every finding a Nielsen severity and an impact score, names 12 root causes and lists the top 15 improvements, each mapped to the work already planned in CC-314, CC-315, CC-099, CC-154 and CC-28x. The main findings: the header is wider than the screen at 768 px on every page; the main chunk is 192.2 kB gzip against the 150 kB budget, partly because chess.js reaches home through `dailyKinds.js`; there are five or six button looks and five or more card looks; result screens stack seven or more actions and their rewards collide; light mode carries little of the arcade identity; the chess lobby shifts by 0.373 CLS; and a visitor's `/friends` never stops loading. Reduced motion is clean, and axe finds no contrast failures. Eight bugs in existing screens are listed for the coordinator to number.
