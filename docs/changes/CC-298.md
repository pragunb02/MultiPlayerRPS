Merge queue, CI side: ci.yml now also starts on `merge_group`, so the queue can test each pull request on the newest main plus the ones ahead of it. Every required job runs there; the render.yaml schema check and the advisory visual jobs are skipped there (reported as passed), and the changelog fragments check runs on pull requests and in the queue. No other workflow starts from the queue. `scripts/workflows.test.mjs` pins the triggers, each job's events and the required check names. DEPLOYMENT.md has the owner's steps (a ruleset with seven required checks and the queue: merge commits, build concurrency 2, groups of 1 to 5, a 30 minute timeout, by UI or `gh api`); once it is on, the coordinator merges with `gh pr merge --merge --auto`, and each merge waits about 10 minutes for CI in the queue.
