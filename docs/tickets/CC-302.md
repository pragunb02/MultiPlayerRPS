## Problem

CLAUDE.md had grown to 190 lines of detail that the other docs also hold, so every agent spent context on it and
parts of it went stale (rule 7 alone carried three merge policies from the same week).

## Fix

CLAUDE.md becomes a 132-line map: the project in one paragraph, the must-always rules (each naming the check that
enforces it, where one exists), the working agreement, decision-first and workflow rules as one line each with
their old numbers, the commands, and a "where things are" table. Every detailed explanation moved to the doc it
belongs in, unless that doc already had it.

**Research note.**

- **How our code does it today.** CLAUDE.md (190 lines) repeated `docs/PROCESS.md` (decision-first detail),
  `docs/DEPLOYMENT.md` (merge policy, deployment impact), `docs/ENGINEERING.md` (principles, testing), the PR
  template (evidence) and `docs/ARCHITECTURE.md` (legacy history, what is built). Other docs cite its rules by
  number ("workflow rule 7", "working agreement item 7", "rule 8"), so the numbers are kept.
- **Sources checked.** The research of 2026-10-20 behind CC-298 to CC-302 (PROGRESS.md, 2026-10-20): a bloated
  agent instructions file crowds out the task and goes stale; keep it short, as a map that links to the docs.

## Acceptance criteria

- **AC-1** Given the new CLAUDE.md, when it is counted, then it has 100 to 150 lines.
- **AC-2** Given each rule of the old CLAUDE.md, when the checklist below is followed, then the rule is found in
  CLAUDE.md or in the named doc.
- **AC-3** Given a must-always rule that a machine checks, then CLAUDE.md names that check.
- **AC-4** Given the branch, then `npm run format:check`, `node scripts/bin/check-tickets.mjs` and
  `node scripts/bin/collect-changes.mjs --check` pass.

## Test

AC-1: `wc -l CLAUDE.md` prints 132 (190 before). AC-2 and AC-3: the checklist below, read by review. AC-4: the
three commands, run locally on the branch.
