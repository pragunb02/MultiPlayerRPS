## Why

Guests earn XP, levels, achievements, streaks and quests, and CC-032 moves all of it to an account on sign-up or
login — but nothing asked them to do it. Guests should be asked when they have something to lose, so they graduate
into accounts. Never nag, never block play.

## Scope

- In (guests only — account holders and visitors without a session never see any of it, and load nothing for it):
  1. **Win card** in the room, under the result and the rematch panel: "Save your progress" with level, XP, wins
     and the daily streak (live from `/api/progress`, `/api/streaks` and their pushes), "Sign up — keep it" and
     "Log in", both `?next=<this room>`. Shown after the guest's first win, and later for a win once they have
     ≥ 50 XP, at most once per room (a rematch won in the same room doesn't bring it back). No toast.
  2. **Level-up toast** gets a "Save it" link (sign-up, `next` = current page) and a × — the same toast, no new one.
  3. **Streak at risk** (daily streak ≥ 2 and `atRisk`): one line on the home quest card and in the profile's
     player console, "Play today to keep your N-day streak — sign up so it's never lost". In the console it replaces
     the general "Sign up to keep your streak and achievements" line (one sign-up line, not two).
  4. **Header**: for a guest with XP > 0 the "Sign up" button reads "Save progress" (same link).
  - After sign-up or login from a guest session that carried something (`carriedOver` with XP or matches), **one**
    toast: "Your progress is now saved: Level L · X XP · M matches" — the account's numbers, read from
    `/api/progress` after signing in. It replaces CC-032's "Welcome! We moved …" toast.
  - Each prompt closes with × and stays closed for the rest of the page session — memory only (no web storage or
    cookies); a reload starts over.
  - **Server**: a guest's seat in a **finished** room now follows the identity on sign-in too (CC-083 only moved
    waiting and running rooms). Without it, "Sign up — keep it" led back to "Can't join this room — This game has
    already started". The seat, result, series and rematch request move to the account; a finished room the account
    itself played in is left alone. This closes CC-113. Since CC-101 the room component is asynchronous and rooms
    live in MongoDB, so the transfer runs through the versioned `change({ decide })` retry like every other change.
- Out:
  - A "session ending soon" prompt: sessions roll 30 days after the last visit (CC-096), so an active guest's
    session never ends soon.
  - The toast pile-up after a win, most visible on phones (CC-099): unchanged here — this ticket adds no toast.

## Acceptance criteria

- [x] Win card after a first win and for later ≥ 50 XP wins, once per room, real numbers, links back to the room.
- [x] "Save it" on a guest's level-up toast; × removes it and later level-ups don't offer it this visit.
- [x] Streak-at-risk line on home and profile for streaks ≥ 2 at risk only.
- [x] Header "Save progress" for guests with XP; plain "Sign up" otherwise.
- [x] One confirmation toast with the account's numbers; nothing when nothing moved.
- [x] Each prompt dismissible for the page session, without web storage.
- [x] Never for account holders or visitors.
- [x] Tests cover the change; lint, format, coverage, e2e (twice), audit pass.
- [ ] Docs updated (BACKLOG status, KNOWN_ISSUES, PROGRESS) — by the coordinator when merging.

## Plan / notes

- `components/SaveProgress/SaveProgressProvider.jsx` (inside the toast provider, around the routes) holds the
  guest's progress and streaks (load once, then pushes; a load answering after a push is dropped), the closed
  prompts and the rooms that showed the card. `saveProgressContext.js` has `useSaveProgress()` and
  `useStreakAtRisk()`; `savedMessage.js` the pure rules (`winWorthSaving`, `movedAnything`, `savedMessage`).
- `ToastProvider` takes an optional `action: { label, to, dismissLabel, onDismiss }`: a link and a × that take
  clicks (the region still doesn't, so a toast never covers a button); such a toast stays 8 s instead of 4 s.
- `DismissButton` — a shared ×, 2.75 rem on touch screens.
- The confirmation reads `/api/progress` rather than using `carriedOver`: `carriedOver` has no level, and after a
  login into an existing account the guest's part alone would contradict the header ("Level 2" on a level-7
  account). If that read fails the toast says "Your progress is now saved." without numbers. No change to the
  sign-up/login responses was needed.
- Header accessible name: "Save progress — sign up". The brief suggested "Sign up — save your progress"; the name
  starts with the visible words instead (WCAG 2.5.3 label in name) and still contains "sign up", so every browser
  test that finds the header's sign-up link by name keeps working.
- Streak-at-risk in the browser test: the shared e2e server can't move its clock for one test, so the test writes
  the guest's `player_stats` as three days of play ending yesterday. For that the e2e MongoDB now runs on a known
  port (`E2E_PORT + 20000`, `E2E_MONGO_URI` in `e2e/personas.js`), bound to 127.0.0.1 like before.
- Colours: tokens only (XP edge on the card, streak edge on the line, primary links). Pairs used are in the CC-087
  table (text/muted/xp/primary on surface and raised, primary-contrast on primary) — all ≥ 4.5:1. No new motion; the
  card is static, so reduced motion has nothing to stop.
