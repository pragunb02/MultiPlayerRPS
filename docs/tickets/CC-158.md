## Why

The only sign of an opponent's lost connection was the word "disconnected", and a player whose own connection
dropped saw nothing for seconds while their presses went nowhere (MATCH_EXPERIENCE A5, A6).

## Scope

- In:
  1. One chip per seat in the players list: connected, thinking with the time left to move (CC-036 limits), away
     from the game screen (CC-207), reconnecting with the grace countdown, offline, or left. A change is read out
     once it has held for a second, with the soft presence sound, so a reload does not read out three changes.
  2. The player's own connection: a "Reconnecting…" banner under the site header after one second, read out at
     once. Controls that need the server already say "Reconnecting" when pressed (CC-164). Closing the connection on
     purpose (signing in or out) is not a lost connection.
  3. On SIGTERM the gateway sends `server:restarting` to everyone before it closes, and the banner says "Server
     restarting, your game is safe" at once.
- Out: the match bar with the turn timer (CC-165), emotes.

## Acceptance criteria

- [x] Chips for every presence, with countdowns as tickers.
- [x] Reconnecting banner after 1 s with controls blocked, gone on reconnect.
- [x] `server:restarting` push and banner text.
- [x] Unit tests (`Seats.test.jsx`, `ConnectionBanner.test.jsx`, `gateway.test.js`), browser tests for a crash and a
      deploy restart (`restart-presence.spec.js`).
