## Problem

Under load, the server integration files and the DAO integration files time out at 5 s and 10 s, the same way
`server.integration.test.js` did before CC-336. Seen while building CC-337: `challengeDao.integration.test.js`
timed out at 5 s in its index test.

### Root cause

The same as CC-336. Each test opened a new database, so each server start, or each DAO's `ensureIndexes`, made
every collection and index again. mongod syncs each new collection and index to disk: 19 ms and 10 ms one at a
time on a quiet Mac (CC-336), and many times that under load. The server files paid about 110 of these per test,
and the DAO files a few per test. At the end, mongod synced every file of every database again as it stopped.
With the shared database, the first test of a server file still paid for every collection and index inside its
own 5 s. That was the next most common failure ("continues a game of Rock Paper Scissors after a restart" in 16 of
20 runs).

## Fix

- Uses `empty(dbName)` in `testing/memoryMongo.js`, which came from CC-336 (#188).
- New `testing/sharedDatabase.js`: `databaseUri(mongo, name)` empties the file's database and gives its address.
  `ownDatabaseNext()` makes the next call give a new database of its own instead.
- The 21 DAO integration files in `persistence/` open their DAOs on one database per file, emptied first. Every
  test that reads the indexes or collections a DAO makes calls `ownDatabaseNext()` first, so it still proves what
  a new database gets (23 tests in 16 files). The CC-182 round-trip test in `roomDao.integration.test.js` keeps
  its own database, as before.
- The six server files that made a database per test run every test on one database, emptied before each test,
  as in CC-336: `accountData`, `bots`, `matchPipeline`, `requests`, `security` and `server.restart`. New
  `testing/serverDatabase.js` (`makeServerDatabase`) starts and stops a server on that database in the file's
  `beforeAll`, under its existing 120 s limit. The collections and indexes are made there, not in the first test.
- Not changed: `admin`, `chessRatings`, `publicNames` and `telemetryPrivacy` already used one database per file,
  and `friends.integration.test.js` has one test, whose index check needs a new database anyway.

No timeout was raised, and nothing is retried or skipped. No app code changed.

### Research

How our code does it now: `server.integration.test.js` already shares one emptied database (CC-336). The other
files each opened `<name>-${++counter}`. Emptying the collections keeps their indexes, so `ensureIndexes`
(Mongoose `syncIndexes`) finds them in place and makes none. Deleting the documents of a collection took 0.14 ms in
CC-336's measurement. An option checked and not taken: one DAO and connection per file instead of one per test.
Mongoose registers a model once per connection, and the contract tests ask for a new DAO each time. Opening a
connection costs no disk sync, so the connections stay as they were.

## Acceptance criteria

- **AC-1** Given a loaded machine, when the changed integration files run, then no test times out because a new
  database was made for it.
- **AC-2** Given a test of the indexes a DAO makes, when it runs, then it reads them from a new database of its
  own.

## Test

Each run below covers all 27 changed files. Two copies ran at once, with 6 CPU burners and `--maxWorkers=2`.
Another builder's 56 CPU burners were running during most of these runs, so the load was far higher than in
CC-336.

| Run                                  | Load      | Result                                                                                                                                                                                                                                                                                                                    |
| ------------------------------------ | --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Before (main)                        | 24 to 277 | 20 of 20 runs failed, 65 failed tests in all, 63 of them at the 5 s limit. "Closes the legacy row" failed in 19 runs and "continues a game after a restart" in 12. A run took 174 to 344 s. The longest mongod stop was 7.9 s                                                                                             |
| Shared database, first test pays     | 44 to 405 | 18 of 20 runs failed, 32 failed tests, 16 of them "continues a game after a restart", the first test of its file. A run took 59 to 121 s. The longest mongod stop was 2.4 s                                                                                                                                               |
| Shared database, made in `beforeAll` | 32 to 375 | 14 of 20 runs passed every test. A run took 56 to 108 s, and the longest mongod stop was 1.4 s. The other 6 ran while the machine stalled: one pair took 4,141 s (over an hour), one pair 248 s, and one run 492 s. Their failures were setup and teardown hooks timing out (10 s, 120 s) and a worker that never started |

`challengeDao.integration.test.js` alone, twice at once with 6 burners at load 33 to 65: 20 of 20 passed before
and after. A run took 5.3 to 6.3 s before and 2.0 to 4.8 s after, and mongod stopped in 0.6 to 1.1 s before and
0.2 to 0.4 s after.
