## Why

The legacy app keeps three near-identical per-game models keyed by typed names, overwrites results and never stores
chess results. Profiles, replays, progression (CC-017) and ratings (CC-042) need one trustworthy record per game.

## Scope

- In:
  - **Rooms** keep a generic action log (`move` / `forfeit` / `expire`, each with server time) plus `matchId` and
    `startedAt`; the log never appears in live views (it would leak pending RPS choices).
  - **`replayGame()`** (games package): seed + options + log rebuild any game exactly; every move is re-validated, so a
    tampered log fails.
  - **Persistence**: MongoDB `matches` collection (Mongoose 9 on the per-instance connection; unique `matchId`;
    index `players.playerId + endedAt`); an in-memory test double; **one shared DAO contract suite run against both**.
  - **Data**: match accessor — idempotent `record`, Date ↔ ms mapping, NotFound translation.
  - **Domain**: match component — record from `room.gameFinished`, history with `outcomeForYou`, full record for
    participants only (others get 404 so ids cannot be probed).
  - **Service**: `GET /api/matches?limit&before` (newest first, `nextBefore` cursor), `GET /api/matches/:matchId`.
  - **Composition root**: background recording with logging; shutdown waits for in-flight writes.
- Out: legacy model removal (CC-029), XP/levels (CC-017), ratings (CC-042), replay viewer UI (CC-041).

## Acceptance criteria

- [x] Every finished game (played out, forfeited or timed out) becomes exactly one match record
- [x] A stored match replays to the same result
- [x] History is private to participants; paging works
- [x] The test double and the real DAO pass the same contract
- [x] Tests, lint, format, coverage, audit pass; ran for real
