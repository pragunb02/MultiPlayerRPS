## Why

A visitor who arrives alone needs someone to play at once. The bots of #47 (`packages/games/src/bots`) could choose
moves but could not sit in a room. ADR-025 sets the rules: a computer player is always labelled as one, its games
never count on a leaderboard or rating, and they give XP and quest progress only within the ADR-021 limits and a
daily XP budget of their own.

## Scope

- In: **identity.** `IDENTITY_KINDS.BOT` and `BOT_CHARACTERS` in `@classicade/shared` (Rocky for Rock Paper
  Scissors, Pip for Tic-Tac-Toe, Queen Vee for chess, each with level picks easy, medium, hard mapped to the bot
  levels). `models/botIdentity.js` gives each character and level a stable id `bot_<character>_<level>` and a `bot`
  label. No session can hold a bot: `createIdentity` has no pattern for the kind.
- In: **seating.** `domain/bots/botComponent.js` `playComputer` creates the room and seats the character, so the game
  starts at once. The seat keeps `bot { character, level }` and every RoomView carries it. A computer player stays
  connected after a restart, and a room with only computer players left closes as empty. A game whose person is away
  closes after the two hour away lifetime, because only people count as away (`roomLifetimes.js`). A player has at
  most 3 games against computers going (`MAX_COMPUTER_GAMES`): starting one more ends the oldest as a forfeit, so one
  socket cannot keep many strong chess searches busy.
- In: **driver.** `domain/bots/botDriver.js` watches every saved room change (new `ROOM_EVENTS.CHANGED`). When a
  computer player has something to do it waits a human-like pause (400 to 900 ms in production, zero in tests), reads
  the room again, checks the moment has not passed, and acts through the room component like a person: a move on its
  turn, a decline of a chess draw offer made on the person's own turn (new optional `Bot.answer`), or accepting a
  rematch the person asked for. It never asks for a rematch itself. It retries a failed write twice. On start up it
  plans for every stored room, so a computer whose turn it was when the last process stopped moves again.
- In: **pure rules.** `domain/bots/botTurns.js` decides what a computer player does from the room alone, with the
  move chosen from the bot seat's own `engine.viewFor` and an RNG seeded from the game's seed and the turn, so the
  same turn gives the same move after a restart.
- In: **rewards (ADR-025).** `fairPlay.js`: the opponent limit is a rolling 24 hours (ADR-021 amendment), each
  character counts as one opponent at every level, and games against computers count toward the hourly limit. A
  counted game against a computer gives at most what is left of `BOT_DAILY_XP` (100) for the UTC day, separate from
  quest XP. The verdict stores it as `credit.botXp [{ playerId, xp, left }]`, so every recount gives the same XP.
  `progress:updated` carries `botXpLeft`. Computer players get no progress, stats, quests or achievements, and
  games against them never move anyone on a leaderboard (`applyMatch`, the weekly XP recount, `countWins`).
- In: **web.** Seats label a computer as `computer · <level>`. The room shows "Rocky is a computer player. This game
  counts…". After the game the XP toast says what is left today, or that the game still counts once the 100 XP are
  used up. `useRoom` keeps the newest view by `revision`, because a computer's update can overtake the answer to the
  move it replies to.
- Out: adaptive difficulty (CC-150), more characters and their personalities (CC-190), quick match (CC-051), the
  history of earlier games for the pattern bot (`history` is empty, see notes), recomputing the bot XP budget when
  a guest's games move into an account (see notes).

## Acceptance criteria

- [x] A computer character sits in a room with a stable identity per character and level, labelled everywhere.
- [x] The driver moves on its turn after a pause, from its own view only, through the normal move path.
- [x] It survives a restart: rooms are in MongoDB, and its turn is played again on start up.
- [x] It never idles (draw offers are declined at once), never asks for a rematch, accepts one.
- [x] Games against computers never reach a leaderboard, give at most 100 XP a day, and count for the limits.
- [x] The opponent limit is a rolling 24 hours.
- [x] Unit tests for every branch, integration tests on MongoDB through the real server, browser tests.
- [x] `npm run lint`, `npm run format:check`, `npm run test:coverage`, `npm run test:e2e` pass.

## Plan / notes

- `roomComponent` changes are small and additive: an optional `botTurns` dependency (its default changes nothing),
  the `CHANGED` event, the `bot` label on seats and views, `markEveryoneAway` leaving computers connected, and a room
  with only computers closing. The gateway gets an optional `botComponent` and forwards `botXpLeft`.
- RoomViews now carry `revision` (the stored room's version). Found while testing: with a pause of zero, the
  computer's reply could reach the browser before the answer to the person's own move or join, and the older answer
  then replaced the newer view. `useRoom` keeps the newer one. The same race existed in principle between two people.
- Rock Paper Scissors levels: the RPS bot has two levels, so Rocky offers Easy (random) and Hard (pattern reader).
  Pip and Queen Vee offer three.
- The bots contract has `history` (earlier games in the room). The room keeps only the current game, so the driver
  passes an empty history. Reading earlier games from match history would need the match records, which are written
  in the background. Follow up with CC-190.
- When a guest's games move into an account (ADR-014), their `botXp` moves as it was. The account's own bot games of
  that day are not taken into account for the 100 XP. The pair and hourly limits are still applied (ADR-021 rule 6).
  Needs a follow up ticket.
- Games against computers do give quest progress and the quests' bonus XP, which reaches the weekly XP board like
  any quest XP. ADR-025 counts quests separately from bot XP. Needs the owner's view whether quest XP earned in
  computer games should stay off the boards.

- Sockets: `service/realtime/computer.test.js` plays each game against its character with the real engines and bots.
- Integration on MongoDB through the real server (`bots.integration.test.js`): a full game against each character,
  the 100 XP limit over five games, and a restart in the middle of Pip's turn.
- Browser (`e2e/computer.spec.js`, desktop and mobile): Play Rocky to a result, the visitor only draws or loses against Unbeatable Pip, chess
  against the Beginner then resign, rematch with Rocky, Back, Forward and reload, New opponent closes the room, the
  "this game counts" note and the XP left toast. `e2e/restart.spec.js`: the server restarts during Pip's game.
  `e2e/match-shell.spec.js` presses every control in the new states (lobby, my turn, result against the computer).
