## Root cause

`apps/server/src/service/http/routes.js` built `createLeaderboardRoutes` without `now`, so the route fell back to
`Date.now`. `leaderboardRoutes.test.js` fixes the date to 2026-10-16 (ISO week 42); the server answered with the real
week, which matched until 2026-10-19 00:00 UTC and then failed every run (W43). In production the effect is none:
both clocks are the real clock there.

## Research

ENGINEERING.md requires time to be injected (pure core, dependencies passed in); every other route in the same file
receives `now`. A test that passes only on certain real dates is a known anti-pattern (time bombs); the fix is the
injection, not a new expected value.

## Verification

The test passes with its fixed clock regardless of the real date; CI on this PR.
