## Why

An audit of every screen's URL, for visitors without a session, guests and signed-in users, found:

- **Login loop:** on `/login`, the header's "Log in" link was `/login?next=/login?next=…`; after logging in the player
  landed on the login form again.
- **Signed-in users** opening `/login` or `/signup` saw the form instead of being sent on.
- **Room links** (`/room/AB2CD3`) didn't name the game; a lower-case code in the URL failed; nothing made one spelling
  canonical.
- **Ids in URLs** (`/play/rps`, `/play/tictactoe`); every tab titled "ClassiCade".
- **"Play" and the logo** both led to `/`, and "Play" was not highlighted inside a game.
- **Legacy URLs** (`/games/chess`, `/games/tictactoe`, `/games/rockpaperscissors`, `/u/:name/userprofile`,
  `/login-signup.html`) answered "not found" for anyone with a bookmark or an old shared link.

## Scope

- In (ADR-011):
  - `/` · `/games/:slug` · `/games/:slug/rooms/:code` · `/login?next=` · `/signup?next=` · `/profile`.
  - Slugs in the shared catalog; one route module (`app/paths.js`) builds every URL.
  - Canonical URLs: each page replaces other spellings (old URLs, ids, case, wrong game for a room).
  - Safe `next`: same-site only, never an account page; header and log in ↔ sign up links pass `next` on unchanged.
  - Signed-in users on log in / sign up go to `next`.
  - Nav "Games" (was "Play"), current on the catalog and inside a game. Page titles everywhere.
- Out: public player profiles `/players/:username` (needs a privacy decision and a public API) — new ticket when
  Stage 1 social features start. Browser persona tests — CC-081.

## Acceptance criteria

- [x] Every screen has one URL and its own title
- [x] Every old URL redirects (replace, so Back doesn't bounce)
- [x] No open redirect, no `next` loops; signed-in users skip the account pages
- [x] Tests cover the change — for visitors, guests and signed-in users
- [x] `npm run lint`, `npm run format:check`, `npm test` pass
- [x] Docs updated (BACKLOG status, PROGRESS)

## Verification

- 819 tests. New: path builders, slug/legacy lookup, `safeNext` (other sites, `//`, `\`, `javascript:`, account
  pages), `returnPathFor`; app-level URL tests: titles for every screen, 8 old URLs and 4 room spellings → canonical,
  signed-in users skipping account pages, `next` not nested, a looping `next` going home, login from a room returning
  to the room, nav state.
- Real browser on a production build: old URLs redirect with the right titles; a created room's URL and invite link
  are `/games/tic-tac-toe/rooms/<CODE>`; Back from a room returns to the lobby (no redirect bounce); an old lower-case
  `/room/<code>` invite opens the canonical room; no console errors. Found and fixed: `/profile` had no title while the
  session loaded.
