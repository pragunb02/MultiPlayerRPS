## Problem

Main's CI on 2d917b7 failed `PlayPage.test.jsx` › "makes a challenge link with the game's options and opens its page":
the test found the challenge page's "Opening the challenge…" and then read `/games/rock-paper-scissors` as the address.
Root cause: the test helper `LocationProbe` recorded the address in a passive effect (`useEffect`), which React may
run after the new page's markup is already in the document, more often since pages load lazily (CC-322). A test that
waited for the new page's text could read the address before the probe ran.

## Fix

The probe records in a layout effect, in the same commit as the page it shows, so once a page's text is found the
address is the new one. Research: React runs layout effects synchronously after the DOM is updated and before the
browser paints, passive effects later (react.dev, useLayoutEffect).

## Acceptance criteria

- **AC-1** Given a test that finds a new page's text, when it reads `url()`, then it gets that page's address.

## Test

The PlayPage test above, and every web test that uses `renderApp` (`vitest related` on the probe: 46 files, 757
tests pass).
