## Problem

A first-time player hits dead ends and developer words when something fails (CC-348, `CLARITY-AUDIT.md` on the
`cc-348-clarity-audit` branch). Root causes: the app's one error boundary wrapped the whole app, so a crash replaced
the header too and offered no button (CL-01); `AppRequestError.message` was the server's own text, which every page
shows under its button or in its error line ("Internal server error", "Malformed request body", "Not in room") (CL-02);
and the room page, log in and sign up said what failed but not why or what to do next (CL-25 to 29, 91 to 93).

## Fix

Every error code gets the player's words in `lib/errors.js`, and the request error carries those words as its message,
so every page that shows an error shows plain words. The server's text stays in `serverMessage`, for logs and tests.
The crash screen sits under a working header with "Reload the page" and "Back to home". The room, log in and
sign up screens take the audit's words, and the gone-room screens end in "Start a new game" or "Back to home".

**Research.** Today: `api.js` and `socket.js` build `AppRequestError` from the server's `{ code, message }`, and pages
render `err.message` in about 40 places. `Button.jsx` shows it under the button. Sources: NN/g, "Error-message
guidelines" (say what happened and how to fix it, in the user's words, never codes); GOV.UK Design System, "Error
message" (say what went wrong and how to put it right, keep what was typed); React, "Catching rendering errors with an
error boundary" (put boundaries around parts of the page so the rest keeps working). Best here: one table on the
client, keyed by the shared `ERROR_CODES`, refined by the `details.reason` the server already sends (move rejections,
room and challenge limits, the daily puzzle), with a fallback for anything unknown. The server's words can then
change without reaching a player, and a test (A4) checks that no code is left out.

**Decisions (coordinator, 2026-10-22).** Crash screen: header stays usable, two buttons, the stale-build reload
(`staleBuild.js`) unchanged. Never show a server's message. Room page, log in and sign up take the audit's exact
words. Gone rooms (audit D2): words only, no new lookup for visitors.

**Small server change.** Joining a room that started or is full now names why in `details.reason`
(`ROOM_JOIN_REFUSALS`, shared), so the page can tell the two apart (CL-27). A blocked pair still gets exactly the
full room's answer (CC-044). Every other refusal a player can meet names its reason the same way, each list in
`packages/shared`: `NAME_REFUSALS` (a reserved or unkind sign-up name), `FRIEND_REFUSALS` (a guest, someone not
played with, a request or link that ended, the friend and waiting limits, the other player a guest, your own link),
`CHALLENGE_REFUSALS` (someone else taking it, your own, sent to someone else, not yours to take back),
`ROOM_REQUEST_REFUSALS` (rematch and draw requests, answers, a move or a claimed win when the game is not on, an
opponent who left or may come back), `ACCOUNT_REFUSALS` (a wrong password or current password, and a player under 13,
`too-young`, which was a bare string before) and `PASSWORD_REFUSALS` (too easy to guess, the length, only spaces, the
same as the current one). Each reason has its own words in `lib/errors.js`. The statuses are unchanged, and so is every
server message but one: `ACCOUNT_MESSAGES.EMAIL_UNAVAILABLE` (shared) now ends "log in. Forgot your password? Tell us
with Feedback and we'll help." instead of "log in or reset your password." (CL-92). It is kept on purpose: the server
and the sign-up page say that one message together (CC-238), and the old one sent players to a reset that doesn't
exist.

**Coordinator, second pass (2026-10-22).** Don't ship screens that became less specific: give each of those refusals
its reason and words, and A4 checks every reason. The crash screen's second button is "Back to home", like the
gone-room screens and within the three-word rule.

**Review (2026-10-22).** Password refusals had lost their reason ("password123" read "That wasn't accepted…"), so
each now names it. "Reconnecting. Your move can wait." was false where time runs on the server, so with a turn limit
or a started chess clock the board and controls say "Reconnecting… Your clock may still be running." The page crash
inside the layout is still counted for usage counts (CC-174), merged from main.

## Acceptance criteria

- **AC-1** Given a page that throws while it draws, when it breaks, then the header still works and the page says
  "This page broke", that games and progress are safe, with "Reload the page" and "Back to home" (CL-01).
- **AC-2** Given any failed request, whatever its code, then the player reads words from `lib/errors.js`, never the
  server's message, and an unknown code reads "Something went wrong. Try again." (CL-02, check A4).
- **AC-3** Given a room that is gone, full, started or missing, then the page says why in the audit's words and offers
  "Start a new game" (when the game is known) and "Back to home"; a session that can't load offers "Try again"
  (CL-25 to 28). The waiting host reads "Waiting for a friend to join" and that the game starts by itself (CL-29).
- **AC-4** Given log in with a wrong email or password, then it says "That email and password don't match. Check them
  and try again." with "Play as a guest instead", and the page says why to log in (CL-91, CL-93). Sign up with an
  email that can't be used points a forgotten password to Feedback (CL-92).
- **AC-5** The connection banner, the board while reconnecting and the 404 page say what was lost or why (CL-06,
  CL-07, CL-37). While a turn limit or a chess clock runs, the reconnecting words say the clock may still be running.
- **AC-6** Given any reason in the shared refusal lists, then the player reads that reason's own words, not only the
  code's general ones.

  It failed first (12 codes, then 27 reasons when every refusal list was added).
- `app/ErrorBoundary.test.jsx`, `components/Layout/PageCrash.test.jsx`: the crash words, both buttons, the header kept,
  and a link in the header drawing the next page. They failed first.
- `pages/RoomPage/*.test.jsx`, `pages/auth.test.jsx`, `ConnectionBanner.test.jsx`, `outcomeText.test.js`,
  `MatchShell.test.jsx`, `App.test.jsx`: each changed message and state, failed first.
- `e2e/screens.spec.js` › "plain errors (CC-350)": the crash screen's two buttons and a server fault on log in, on
  desktop and phone.
- Server tests check each new `details.reason` (friends, challenges, room requests, claimed wins, passwords, the
  password rules and the easy-password screen).
- `pages/auth.test.jsx` and `AccountSettings.test.jsx`: an easy password at sign-up, and every new-password refusal on
  the change form, each in its own words. No test expects the general line for a password. They failed first.
- `outcomeText.test.js`, `MatchShell.test.jsx`: the honest reconnecting words with a turn limit or a running clock,
  failed first. `PageCrash.test.jsx`: the crash is counted once, failed first without the layout's `onError`.
- Tests that asserted a server's own text now assert the player's words.
