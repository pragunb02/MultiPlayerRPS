## Scope

- In:
  - **Strict CSP** for the new stack: `default-src 'self'`; scripts, styles, fonts, connections only from our origin; images
    from our origin or `data:`; `object-src 'none'`; `frame-ancestors 'none'` (+ `X-Frame-Options: DENY`); `base-uri` and
    `form-action` locked; `upgrade-insecure-requests` in production. **No `unsafe-inline`/`unsafe-eval`** — the last two
    inline `style=` attributes in the app were removed (CSS class; native `<progress>`).
  - **CSRF defence (ADR-010)** on every state-changing `/api` request: SameSite=Lax cookies (existing) + Origin must be an
    allowed origin when present + JSON-only bodies (415 otherwise). New error code `UNSUPPORTED_MEDIA_TYPE`.
  - **Serving the built web app** from the server (`WEB_DIST_DIR`, validated at boot): deep-link fallback to `index.html`
    for non-API HTML requests; hashed assets cached for a year, `index.html` and other files revalidated; API 404s stay JSON.
- Out: switching production to the new stack (CC-029).

## Verification

- 650 tests incl. CSRF (cross-site refused, own origin and non-browser allowed, non-JSON refused, safe methods untouched),
  CSP directives, framing, static caching, deep links, API-404 preservation, boot failure without a build.
- Production build served by the server itself, two real browsers played chess to checkmate: all 32 piece images and the
  lazy chess chunk loaded, WebSockets worked, **zero CSP violations or browser errors**. A cross-site POST returned 403.
