## Why

The legacy Tic-Tac-Toe let the browser decide the board and the winner (SEC-04), lost player 1 when creating the
room (BUG-03), and could announce a win twice when one move completed two lines (BUG-04).

## Scope

- In: `tictactoeEngine` — seeded starter plays X; strict moves `{ cell: 0–8 }` (out-of-range/non-integer →
  `INVALID_MOVE`, occupied → `ILLEGAL_MOVE`, out of turn → `NOT_YOUR_TURN`); the server detects every win and draw and
  produces exactly one outcome; no options; identical view for everyone. Shared `TTT_MARKS`, `TTT_CELLS`. Registered.
  Shared socket test helpers (`testing/socketClients.js`) replace three copies of the same setup code.
- Out: web board (CC-024), bots (CC-039), rematch alternating the starter (CC-037).

## Acceptance criteria

- [x] Passes the shared engine contract kit
- [x] All 8 lines, draws, a win on the 9th move that also completes two lines (one result), fair starter across seeds
- [x] Clients cannot decide moves or results (extra fields like `winner` in a move are ignored)
- [x] Playable end to end over sockets

## Verification

- 400 tests (5 consecutive green runs); engine 100 % lines/branches; lint 0; audit 0.
- Live game against the real server + MongoDB: X wins on the 0-4-8 diagonal; a move after the end → `CONFLICT`.
