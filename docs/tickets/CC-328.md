## Problem

ADR-075 decided how ClassiCade does celebrations and seasonal looks (an effect registry, one `EffectHost`, our own
canvas particle module, lazy chunks and budgets), but none of it exists. The win confetti is 24 CSS spans with a
`var()` inside its keyframes (the one keyframe breaking the contract), the level-up burst and the confetti are each
portalled by their own component, and there is no way to dress the arcade up for Diwali on 6 November without
hardcoding it into whatever page wants it, and then forgetting to take it out.

## Job to be done

When something good happens, or a festival comes round, players want the arcade to celebrate with them for a moment,
so it feels alive and warm, without slowing their phone, covering a button or staying past its season.

## Appetite

M (up to 6 agent-hours), in two PRs: (1) the registry, `EffectHost`, `useEffects().play`, the particle module and the
three celebration scenes; (2) the theme system, the Diwali theme and the winter theme. **Cut line**, dropped first in
this order: the winter theme (it waits for its own small PR before 2026-12-15); the achievement scene (CC-099 then
uses the level-up scene for both); the console's "Preview in this tab". The registry, the host and its gates, the
Diwali theme and the budget tests are never cut.

### Celebrations

The particle colours come from the five tokens `--effect-ink-1` to `--effect-ink-5`, read once per play with
`getComputedStyle`. They are not in the token files: each scene falls back to `--color-neon-gold`,
`--color-neon-accent`, `--color-neon-xp`, `--color-neon-tictactoe` and `--color-neon-rps`, and a theme sets them
under its attribute. So under Diwali a win bursts in diya gold and marigold, and no scene knows Diwali exists.

| Name          | Kind        | When (who calls `play`)                              | Particles (low-end tier) | Duration | Shape                                                                                               | Sound (ADR-018, CC-208)       | Budget |
| ------------- | ----------- | ---------------------------------------------------- | ------------------------ | -------- | --------------------------------------------------------------------------------------------------- | ----------------------------- | ------ |
| `win_burst`   | celebration | A real win, once (CC-327 now, CC-099's beat 1 later) | 120 (40)                 | 1200 ms  | Two cones from the result's top corners (or `origin`), confetti rectangles and stars, gravity, spin | none (the result sound plays) | 2 kB   |
| `achievement` | celebration | An achievement beat (CC-099 beat 5)                  | 48 (16)                  | 900 ms   | A ring of small stars from the badge (`origin`), out and fading, no gravity                         | none (the beat's chime)       | 2 kB   |
| `level_up`    | celebration | A level-up beat (CC-099 beat 4)                      | 90 (30)                  | 1200 ms  | Twelve rays and sparks rising from `origin`, then falling                                           | none (the beat's sound)       | 2 kB   |

No celebration has a flag: they replace effects players already get (`Confetti`, `LevelUpBurst`). The old
`art/effects/` components stay until CC-099 moves its callers to `play`; their removal, and the `confetti-fall`
keyframe with them, is CC-099's.

### The theme system

One registry entry per theme: `{ name, kind: "theme", ticket, flag, window: { from, to }, removeBy, particles,
durationMs, budgetKB, greeting: { hi, en }, load }`. Its module exports `start(canvas, api)` for the entrance burst
and imports its CSS module, which holds only `:root[data-event-theme="<name>"]` rules.

1. **What a theme may change.** Only the tokens in `THEMEABLE_TOKENS`: `--gradient-hero`, `--grid-line`,
   `--glow-primary`, `--glow-gold`, the `--color-neon-*` inks, `--effect-ink-1` to `--effect-ink-5` and
   `--event-ambient` (the ambient picture). Never a status or player role, a text colour or a surface, so the
   contract's contrast never changes. A test parses each theme's CSS and fails on any other property.
2. **Ambient background.** `global.css` draws `body` with `background-image: var(--event-ambient, none), <today's
grid>`; the theme sets `--event-ambient` to its static SVG (`url(./diyas.svg)` resolves to our origin, allowed by
   `img-src 'self'`). It is still: no animation, no canvas, no video (ADR-016 amendment, point 1). It sits in the
   page's top padding band under the header and in the footer band, where no text is.
3. **Particles.** At most one entrance burst per visit (in memory, no storage), on the home page only, 1.5 s at
   most, after the page is idle, never during a game, never while a celebration plays.
4. **No component has theme code.** The host sets `data-event-theme` on `<html>`; `EventGreeting` reads
   `useEventTheme()`. An ESLint `no-restricted-imports` rule refuses `effects/scenes/*`, `effects/themes/*` and
   `effects/particles.js` outside `apps/web/src/effects/`, and a test fails on any theme name in a file outside it.
5. **Light and dark.** Each theme writes its overrides for both: `:root[data-event-theme="x"]` and the same inside
   `@media (prefers-color-scheme: dark)`; when CC-280 adds `data-theme`, it adds the matching selectors.
6. **Turning on.** Flag on (ADR-073 point 5) and today's India day inside the window, checked at start and at India
   midnight. A theme past its `removeBy` fails a test, as flags do.
7. **Preview.** The console's Flags tab gets "Preview in this tab" next to a theme's flag (admins only, this tab
   only, ignores the window, never stored), so the owner sees a theme before its window opens.

### The Diwali 2026 theme

- **The date, verified.** Lakshmi Puja (Diwali) is **Sunday 8 November 2026**; Dhanteras is Friday 6 November and
  Bhai Dooj Wednesday 11 November (Drik Panchang, "Diwali Puja Calendar 2026", read 2026-10-21; it lists Narak
  Chaturdashi with Lakshmi Puja on the 8th and Govardhan Puja on Tuesday 10 November). New moon on 9 November 2026
  (12:32 IST) agrees.
- **Window:** `{ from: "2026-11-06", to: "2026-11-11" }`, India days, inclusive: Dhanteras to Bhai Dooj, the five
  days people celebrate. **removeBy and the flag's removeBy: 2026-11-30.**
- **Flag:** `event_diwali_2026`, audience everyone, `client: true`, rollout off in code, success "A player who saw the
  theme started a game in the same visit."
- **Look.** Warm gold over the night arcade. Hero gradient light `linear-gradient(135deg, #4a1f7a 0%, #a3243f 100%)`
  (white text 11.9:1 and 7.3:1, the hero focus ring `#ffe08a` 9.2:1 and 5.7:1), dark `linear-gradient(135deg,
#24104a 0%, #5e1630 100%)` (16.8:1 and 12.9:1). Grid line `rgb(245 183 0 / 10%)` light, `rgb(255 209 102 / 9%)`
  dark. `--glow-primary` warms to `0 0 0 1px rgb(255 183 3 / 40%), 0 6px 20px rgb(255 158 27 / 30%)` in light and
  `0 0 0 1px rgb(255 209 102 / 50%), 0 0 24px rgb(255 158 27 / 40%)` in dark. Neon inks: gold `#ffd166`, accent
  `#ff4f8b` (rangoli pink), rps `#ff9e1b` (marigold), xp and tictactoe unchanged. Effect inks: `#ffd166`, `#ff9e1b`,
  `#f5b700`, `#ff4f8b`, `#fff1c1`.
- **Ambient:** `diyas.svg`, a 3rem band of small clay diyas with still flames on a marigold string, about 3 kB, drawn
  by us in the arcade stroke (credited in CREDITS.md as `LicenseRef-ClassiCade`). No firecrackers, no deity, no
  religious symbol beyond the lamp, which Hindus, Sikhs (Bandi Chhor Divas) and Jains share.
- **Particles:** "sparks": 60 warm gold motes (20 on the low-end tier) rising gently from the band's diyas and
  fading, 1200 ms, no gravity, no flashing (WCAG 2.3.1: no luminance flash, nothing over 3 per second).
- **Copy (one line, on the home hero only, above the headline):** Hinglish "Diwali ki shubhkamnayein! Roshni aur
  khushiyan tumhare saath." English "Happy Diwali from all of us at ClassiCade." The same for every player; no ask,
  no countdown, no "limited time".

### Reduced motion

Under `prefers-reduced-motion: reduce` (and CC-280's `cc.look.motion` once it exists): `play` resolves at once and
draws nothing; a theme applies its colours, ambient picture and greeting, with no burst. The canvas is never
created. Every celebration's meaning is already in text on the page (ADR-012 point 3).

## Non-goals

- Calling `play` from the reward beats (CC-099) and from the result (CC-327).
- Holi, New Year, cricket and board skins (CC-205 keeps them, built on this system).
- Event quests and badges (CC-055).
- The theme and motion settings (CC-280).
- Sounds for themes: none.

## Rabbit holes

- **A theme restyling components.** It may only change the listed tokens; a test enforces it.
- **Remembering "seen the burst today" in storage.** Not worth an allowlisted key; once per visit in memory.
- **Canvas size and DPR on rotate.** Resize on `resize` at most once per frame; DPR clamped to 2.
- **Prefetching the theme on the first route.** The theme chunk loads after the first paint, at idle, never with
  save-data; until it arrives the page simply has its normal look.

## Threat model

1. **What are we building?** Client-side decoration, switched by flags the server already serves, and a console
   preview button.
2. **What can go wrong?** A theme's CSS or SVG loads from another origin, or a preview reaches a non-admin.
3. **What are we doing about it?** Every asset is a same-origin chunk under the unchanged CSP; the e2e `players`
   fixture fails on any violation. The preview is inside the admin-only console route (ADR-036) and stored nowhere.
4. **Good enough?** Yes.

## Privacy checklist

- **Data:** none; the flag answer is a boolean.
- **Retention:** none.
- **Who sees it:** everyone in the window, the same for all.
- **Minors (ADR-028):** the same look for everyone; no ask, no name.
- **Defaults:** themes off in code; reduced motion respected.

## Alternatives considered

- Every library in EFFECTS-STACK section 4; the decision stands.
- **Hardcoding Diwali on home.** Exactly what ADR-075 exists to stop.
- **A theme as a full token set.** Lets a theme break contrast; decoration tokens only.

## Research (written before any code)

1. **How our code does it today.** `art/effects/` draws `Confetti` (24 CSS spans with `var()` in `confetti-fall`),
   `LevelUpBurst`, `StreakFlame` and `XpPop`, each rendering nothing under reduced motion; `ResultCelebration` and
   `ProgressToasts` portal them to the body (CONTRACT.md section 5). Flags are ours (`flags.js`, `useFlag`). There is
   no theme hook: CC-280's `data-theme` is not built.
2. **How others do it.** The measured evaluation is EFFECTS-STACK sections 4 and 5 (2026-10-21). Google Doodles and
   Duolingo's seasonal app icons (general knowledge, high confidence) dress up for a festival with art, not with new
   layouts, and leave on schedule. Drik Panchang's 2026 Diwali calendar (read 2026-10-21) gives the five days. WCAG
   2.3.1 (three flashes) and 2.3.3 (animation from interactions) set the motion rules.
3. **What is best for ClassiCade.** Most players are in India on mid-range Android: a warm, still Diwali look with
   one short burst is the festival feeling without the battery cost. Decoration tokens only keep every screen as
   readable as on any other day, and the registry's `removeBy` makes sure the lamps come down.

### Build notes (2026-10-21)

- **The first route holds a loader, not the host.** With the registry, gates and host all on the first route they
  were 3.1 kB of gzip (registry alone 0.74 kB, over its 0.5 kB). So `EffectHost.jsx` is a 0.27 kB loader that brings
  `HostRuntime.jsx` (queue, gates, canvas, themes) and the registry in their own chunk once the page is idle, long
  before a game can end; a `play` before then is dropped like any other. On the first route: the loader, `channel.js`
  (the in-memory link between `play`, the host, the greeting and the preview), `EventGreeting` and `useEventTheme`.
- **Greetings live in each theme's module** (`export const greeting`), not in its registry entry, for the same
  budget. They show with the theme's colours, when its chunk arrives.
- **Flags are asked only for themes whose window holds today** (India), so no request and no exposure on the other
  days of the year; asked again at India midnight.
- **Save-data:** the theme's chunk is never fetched, so the page keeps its usual look (the attribute is set, nothing
  else changes).
- **The ambient band** sits in `main`'s top padding (2rem, `--space-8`) and along the bottom padding of the page
  (1.5rem, `--space-6`), the bands where no text is, so the 3rem drawing is scaled to those heights. Vite inlines
  the SVG as a `data:` URL, which `img-src 'self' data:` already allows.
- **A theme's CSS module is exported** (`export { tokens }`): with only a side-effect import the build drops a CSS
  module that has no classes, and the theme would have no colours. `themes.test.js` checks it.
- **Live play holds theme bursts only** (`useInGame`): a celebration is called from the result as the game ends,
  before the host may have heard the game is over, so it is not held back; a game starting stops what plays.
- **The queue:** a dequeued celebration is gated with `busy: false`, so only the late start and the real gates can
  drop it, however many wait behind it (review fix).
- **India midnight:** the day is read again every time the timer fires (and the timer set again), when the tab is
  shown and when it gets the focus, so a tab that slept through midnight takes a theme down on waking (review fix).
- **The 150 ms/s budget is the page's total** while an effect plays (design lead, 2026-10-21, on review). To hold it
  on the throttled phone: each frame is one path and one fill per ink with only the last frame's box cleared, the
  canvas is at most 1.5× (ADR-075 allows 2), a phone-sized screen (under 40rem) draws at most
  `PHONE_PARTICLE_CAP` = 80 particles (so 80 for `win_burst` and `level_up` there, 120 and 90 on larger screens),
  and the particle module is warmed once per visit at idle on a 1 × 1 canvas nobody sees, because its first run
  cost about twice a warm one (where the browser has `requestIdleCallback`; never under reduced motion or
  save-data).
- **`play` rejects an unknown name** once the host is up (a `RangeError`), instead of throwing synchronously, so the
  registry can stay off the first route.
- **Flag hygiene** now also reads a registry entry's `flag: "name"` as code reading that flag
  (`apps/server/src/testing/flagSources.js`).
- **The layout probe** in `e2e/flags.spec.js` compares each themed page with the same page on a day without a
  theme (CC-154's helper does not exist yet): until CC-324 lands, the header alone is 45 px wider than a 768 px
  window, which is not the theme's.
