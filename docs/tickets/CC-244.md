## Research (written before any code)

To be written by the builder before any code: how our code does it today, how other products do it (with sources
and dates), and what is best for ClassiCade.

## Why

Today nothing records presses, page views or funnels, and the privacy page promises no third-party analytics. The owner wants every behaviour emitted so trends can guide work later (2026-10-18). Before CC-173 to CC-178 build anything, one list must say what we record and why.

## Scope

- In: docs/analytics/EVENTS.md: each event's name, trigger, fields, purpose, retention, minors' rule and opt out; mapped to the console questions it answers; the privacy page wording.
- Out: building the client or ingestion (CC-174, CC-175).

## Acceptance criteria

- [ ] Every event has a purpose and a retention; none carries identifying data beyond what ADR-028 allows
- [ ] The owner accepts the list
- [ ] Tests cover the change
- [ ] `npm run lint`, `npm run format:check`, `npm test` pass
- [ ] Docs updated (BACKLOG status, KNOWN_ISSUES, PROGRESS)
