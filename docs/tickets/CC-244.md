## Research (written before any code)

### 1. How our code does it today (origin/main at `61b3bb2`, read on 2026-10-18)

1. **Nothing is recorded as an event.** There is no telemetry client, no ingestion route and no events collection.
   The privacy page says "no analytics services" and the footer says "No ads, no trackers"
   (`apps/web/src/pages/LegalPages/PrivacyPage.jsx`, `apps/web/src/components/Footer/SiteFooter.jsx`).
2. **What already exists to build on.**
   1. Every control has a stable `data-cc-control` name (ENGINEERING.md, CC-170), for example `header.login`,
      `room.rematch.ask`, `chess.square`. About 90 names today. These can be the `control` field of a press event
      with no free text.
   2. Every route is listed once in `apps/web/src/app/paths.js` (ADR-011). A page view can name the route template
      (`/games/:slug/rooms/:code`) instead of the URL, so room codes and `next=` never reach an event.
   3. Error codes are a closed list (`ERROR_CODES` in `packages/shared/src/errors.js`), and so are room close reasons,
      not-counted reasons and socket events (`packages/shared`). Events can carry those codes and nothing typed.
   4. Server lines in the logs already say "room created", "joined room", "left room", "rematch requested", "match
      recorded" and "room closed" with the reason. They are logs (7 days on Render), not events.
   5. Finished matches, progress, transfers and accounts are already in MongoDB. The owner console (CC-233, PR #64,
      not on main yet) builds aggregates from them with groups under 5 hidden.
3. **Decisions already taken.** PRODUCT_VISION D15 and CC-173: first party only, anonymous, opt out, aggregate counts
   only for minors and unknown ages, every event carries the build version. ADR-028.1: unknown age means minor, so
   every guest and every account without a birth year (all of them today, CC-152 is not built) is treated as a
   minor. GROWTH.md 6.1 adds: honours GPC, no third-party analytics. CC-175 keeps raw events 30 days, CC-176 keeps
   daily totals 13 months.

### 2. How others do it (sources fetched 2026-10-18)

**Event models.**

1. **Plausible** counts visitors with no cookie and no stored identifier: a daily id is a hash of a daily salt, the
   site domain, the IP address and the User-Agent, and "the salt is rotated and deleted every 24 hours", so a
   visitor cannot be followed from one day to the next. It keeps the host and path, drops query strings other than
   campaign ones, and never stores the raw IP or User-Agent (https://plausible.io/data-policy, last updated
   September 2026). Custom events are a name plus custom properties, and a property name must be spelled the same in
   every call. Its docs show how to strip a URL that carries sensitive data (https://plausible.io/docs/custom-event-goals).
2. **PostHog** recommends lowercase snake_case, present tense verbs from a fixed list (click, submit, create, view),
   a `category:object_action` name, property names like `object_adjective`, `is_` or `has_` for booleans, and a new
   versioned event name when a flow changes. Names are "fixed strings in your code, never generated dynamically"
   (https://posthog.com/docs/product-analytics/best-practices). Anonymous events "only capture the event data and
   none of the person data", and with `person_profiles: 'identified_only'` no person profile is made until
   `identify()` is called (https://posthog.com/docs/data/anonymous-vs-identified-events). Memory persistence keeps
   its id only for one page view (https://posthog.com/docs/libraries/js/persistence).
3. **Simple Analytics** drops the IP "from every single request", stores no cookie or local storage, decides a
   unique visit from the referrer's host only, and links events with a page id and an in-memory page-load id that are
   "not linked to a person" and never stored on the device. Event names are lowercase letters, digits and
   underscores, at most 200 characters (https://docs.simpleanalytics.com/what-we-collect,
   https://docs.simpleanalytics.com/events).
4. **GA4** event names start with a letter, use only letters, digits and underscores, are case sensitive and at most
   40 characters, parameter values at most 100 characters, at most 25 parameters per event, and names starting with
   `_`, `firebase_`, `ga_` or `google_` are reserved (https://support.google.com/analytics/answer/13316687,
   https://support.google.com/analytics/answer/9267744). Google bans PII in what is sent: "Both the URL path and
   parameters must be free of PII", and form input must be stripped (https://support.google.com/analytics/answer/6366371).

**Minors.**

5. **DPDP Act 2023, section 9.** A child is under 18. 9(1) needs verifiable parental consent before processing a
   child's personal data. 9(3) bars "tracking or behavioural monitoring of children" and targeted advertising.
   9(4) and the Fourth Schedule of the DPDP Rules 2025 exempt some classes and purposes: health, schools, creches and
   school transport, functions in the child's interest, creating an account used only for email, keeping harmful
   content away, and confirming someone is not a child. **None of them covers analytics or service improvement**
   (https://www.dpdpa.com/dpdpa2023/chapter-2/section9.html, https://dpdpa.com/schedule/schedule4.html). Rule 10
   says how a parent's consent and adulthood are checked (https://dpdpa.com/dpdparules/rule10.html). The Rules were
   notified on 14 November 2025, and the remaining provisions apply from 13 May 2027
   (https://en.wikipedia.org/wiki/Digital_Personal_Data_Protection_Act,_2023). So the safe reading is: no event about
   a minor or unknown age player may be linked to that player, even by a hashed id. Counts with no id are not
   personal data, so they stay possible.
6. **COPPA (United States), under 13.** A persistent identifier, "a customer number held in a cookie" for example, is
   personal information (16 CFR 312.2, https://www.law.cornell.edu/cfr/text/16/312.2). The FTC lets an operator
   collect one without parental consent only for "support for the internal operations", which includes analytics
   that "maintain or analyze" the site's functioning, and only if it is never used to contact a person or "to amass a
   profile on a specific individual" (FTC COPPA FAQ J.5 and J.7,
   https://www.ftc.gov/business-guidance/resources/complying-coppa-frequently-asked-questions, rule amended
   22 April 2025). COPPA is looser than the DPDP Act here, so the DPDP Act sets our rule.
7. **UK Children's code, standard 12.** Profiling is "off" by default for children unless it is essential to the
   core service, and each profiling purpose has its own setting
   (https://ico.org.uk/for-organisations/uk-gdpr-guidance-and-resources/childrens-information/childrens-code-guidance-and-resources/age-appropriate-design-a-code-of-practice-for-online-services/12-profiling/).
8. **Global Privacy Control.** The browser sends `Sec-GPC: 1` and exposes `navigator.globalPrivacyControl`
   (https://w3c.github.io/gpc/). California's CCPA requires it to be honoured as an opt out
   (https://globalprivacycontrol.org/).

### 3. What is best for ClassiCade

1. **Names like GA4 and PostHog, without the category prefix:** lowercase `object_action` in snake_case, at most 40
   characters, fixed strings in one shared module (CC-174). Property names in snake_case, values from closed lists
   (control names, route templates, error codes, game ids), never free text, never a URL, never a room code, email,
   username or IP.
2. **Two tiers, decided per event by the age signal**, which is how D15 and ADR-028 already read:
   1. **Counts tier (everyone, including every minor and unknown age player, so every player today).** The event
      carries no player id, no session id and no device id. Like Simple Analytics, a random page-load id that lives
      only in memory may link the events of one page load (needed for dead and rage clicks and the time to first
      move), and it is dropped at ingestion once the totals are made. Raw events of this tier are personal data at
      most for 30 days, then only daily totals exist.
   2. **Adult tier (only accounts that stated an adult birth year, after CC-152).** The event may carry a hashed
      player id (a keyed hash with a secret held only by the server, like `utils/networkKey.js`), so D1, D7 and WRP
      can be measured from events. The hash is rotated, and raw events are deleted after 30 days.
3. **Retention measured from what we already store.** WRP, D1 and D7 for guests are counted from `matches` (the
   service's own records, CC-233), not from events, so no behavioural event about a minor is ever linked to them.
   Events add the steps before a match (visit, first press, sign-up form) only as counts.
4. **Opt out and GPC.** A switch on the privacy page and in the profile, and `navigator.globalPrivacyControl === true`
   or `Sec-GPC: 1`, stop every event at the client and are checked again at ingestion. Do Not Track is treated the
   same way (Simple Analytics does), because it costs nothing.
5. **The list is "Proposed"** until the owner accepts it, and CC-173 records the decision as an ADR. Open questions go
   to the owner.

## Why

Today nothing records presses, page views or funnels, and the privacy page promises no third-party analytics. The owner wants every behaviour emitted so trends can guide work later (2026-10-18). Before CC-173 to CC-178 build anything, one list must say what we record and why.
