## Why

Players need to start a room, invite a friend and follow the room's lifecycle. The legacy UI copy-pasted ~150 lines of
share-menu code into three files (DEBT-03), mixed five overlapping stylesheets (DEBT-05) and said "Tic Tac Toe" in every
share message (BUG-12).

## Scope

- In:
  - **Pages**: `/play/:gameId` (game options + create room; join by code) and `/room/:code` (joining, waiting with invite,
    playing, finished with the result from your point of view, closed, errors) — a shared link works for brand-new
    visitors (guest session first).
  - **Client game registry** (`src/games/registry.js`): each game contributes an options form (RPS best-of, chess time
    control) and, from CC-024, a board; a clear fallback otherwise.
  - **Hooks**: `useCreateRoom`; `useRoom` (join on connect, apply this room's pushes only, rejoin after reconnect,
    `move`, `leave`; navigating away never forfeits).
  - **Components**: `ShareRoom` (link, copy, native share sheet, correct game name), `Seats`, accessible `Modal`
    (focus in, Escape, focus restored), toasts (polite live region), `ProgressToasts` (+XP / level-up).
- Out: game boards (CC-024), auth/profile (CC-025), rematch (CC-037), spectators (CC-057).

## Verification

- 681 tests (5 consecutive green runs); 54 web tests incl. lobby options, room lifecycle, reconnect rejoin, forfeit confirm.
- Visual check in real browsers (Playwright, two players, desktop light + mobile dark) against the real server and
  MongoDB: create → invite link → join → forfeit dialog → "You won!" + "+30 XP" toast. Fixed two mobile issues found in
  the screenshots (wrapping button, toast overlapping the footer).
