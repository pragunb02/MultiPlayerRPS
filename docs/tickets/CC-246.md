## Research (written before any code)

To be written by the builder before any code: how our code does it today, how other products do it (with sources
and dates), and what is best for ClassiCade.

## Why

The owner asked what happens when a player refreshes or leaves a room (2026-10-18). The rules live in `roomLifetimes.js`, the room state machine and many browser tests, but there is no single table of each situation and what each player sees.

## Scope

- In: docs/ux/ROOMS.md: for each room state (waiting, playing, finished, closed) and each event (refresh, closed tab, Leave, lost network, server restart, the other player gone), what each player sees and can do; a browser test per row, reusing existing ones.
- Out: changing behaviour (any gap becomes a bug ticket).

## Acceptance criteria

- [ ] Every row has a passing browser test
- [ ] Gaps found are bug tickets
- [ ] Tests cover the change
- [ ] `npm run lint`, `npm run format:check`, `npm test` pass
- [ ] Docs updated (BACKLOG status, KNOWN_ISSUES, PROGRESS)
