## Research (written before any code)

1. Today: main's run 39098491354 (merge of #88) and docs-only PR #95's run 39099290242 fail in part 4 of the
   browser tests. Three tests fail, and the browser checks are required, so no PR can merge:
   - `waking-up.spec.js:132` on desktop, mobile and Firefox: the page's "still waking up" line is not shown at
     line 140.
   - `screens.spec.js:145` on mobile: the click on the header's Menu button times out, "`<nav aria-label="Main">`
     intercepts pointer events".
   - `user.spec.js:82` on mobile: the click on Log out times out.
2. Elsewhere: Playwright's `toBeVisible` checks the element's box and computed style, not whether anything was
   painted, so an unstyled element counts as visible before a render-blocking stylesheet applies. CSS animations
   only exist once the stylesheet that declares them applies (`document.getAnimations()` is empty before). Flex
   items have `min-width: auto`, so a row of words that can't wrap sets the row's smallest width, and a page
   whose content is wider than a phone widens the layout viewport (the phone zooms out).
3. For us: fix each cause where it is. The app where the app is wrong (the seat row), the test where the test
   assumed something the app never promised (the stylesheet having applied). No assertion, timeout or retry
   is loosened.

## Root cause

1. **Waking-up test, a race in the test.** The test loads with `waitUntil: "commit"` and checks the page's screen
   with `toBeVisible`, which passes as soon as the HTML is parsed, before the stylesheets arrive. It then moves
   every animation to 11 s, but there are none yet. When `index-*.css` applies a few ms later, the line's 10 s
   delay starts from zero and the line is hidden. The CI trace shows `index-*.css` finishing about 15 ms after
   the animations were moved. Locally the stylesheet comes first, so it passed. Holding the stylesheet back until
   after the move reproduces the CI failure exactly at line 140. A browser never paints before the stylesheet,
   so players never saw this; the app is right.
2. **Room page wider than a phone, an app bug.** A seat row is a flex row that never wraps: the token, the dot,
   the name, "you", "host" and "connected" (added by CC-158). With a 15 character name it needs 449 px, so on a
   412 px Pixel 7 the whole page became 449 px wide. Before CC-259 that only zoomed the page out. Since CC-259
   (#90) the header's Menu button sits at the right edge, which was now off the phone's screen, and the
   navigation strip lay over where the press landed, so Log out could not be reached. CC-270 (phones 451 px wide
   after a win) is most likely the same row; to confirm there.
3. **Sign-up test, a merge clash.** #69 (CC-238) added a test that presses Log out straight in the banner. #90
   (CC-259) moved Log out into the phone menu and changed every other test to open it with `header(page)`. Each
   PR was green alone; together the new test presses a hidden button on phones.

## Fix

- `e2e/waking-up.spec.js`: `waitAsIf` first waits until the page's screen has its stylesheet layout
  (`display: grid`), then moves the animations. The check itself is unchanged.
- `apps/web/src/components/Seats`: the seat row wraps, and the name may break, so a room is never wider than the
  screen. `screens.spec.js:145` now checks that the room page is exactly as wide as the screen.
- `e2e/user.spec.js`: Log out and Log in are pressed through `header(page)`.

## Verification

- Holding the stylesheet back until after the move: the old test fails at line 140 as in CI; with the fix it
  passes (stylesheet released 300 ms after the page).
- The three specs on Chromium desktop and mobile, and on Firefox, three times each (`--repeat-each=3`).
- `match-shell.spec.js` chess: the six known layout cases (CC-172) are still expected failures (`test.fail`).
- `npm run lint`, `npm run format:check`, `npm test`.
