## Why

The legacy app is one 595-line file with server code living under `client/` (DEBT-01, DEBT-02). Every following
Stage 0 ticket needs a clean home: a testable server, and a shared package for constants used by server and web.

## Scope

- In:
  - npm workspaces at the root (`apps/*`, `packages/*`).
  - `apps/server` (`@classicade/server`): ES modules, Express 5, config module, `createApp()` factory,
    `startServer()` with graceful shutdown, `/api/health`, `/api/games`, JSON 404 + error responses.
  - `packages/shared` (`@classicade/shared`): game catalog constants (first shared module).
  - Root scripts, ESLint config for ESM code, tests.
- Out (own tickets):
  - `packages/games` + engine interface → CC-014
  - `apps/web` (React + Vite) → CC-022
  - Structured logger + full error handling → CC-012
  - Sessions, Mongo, sockets → CC-013, CC-016

## Acceptance criteria

- [x] `npm install` at the root installs all workspaces
- [x] `npm run dev:server` starts the new server on port 4000 (legacy app keeps running on 8080 via `npm run dev`)
- [x] `GET /api/health` → `200 {"status":"ok"}`; `GET /api/games` → game list from `@classicade/shared`
- [x] Unknown routes → JSON 404; thrown errors → JSON 500 without leaking stack traces
- [x] Config is validated at boot; invalid values fail fast with a clear message
- [x] SIGINT/SIGTERM close the server gracefully
- [x] Tests cover the above; `npm run lint`, `npm run format:check`, `npm test` pass

## Plan / notes

- New server reads its own `apps/server/.env` (Node's built-in `process.loadEnvFile`, no dotenv) so it never
  clashes with the legacy root `.env`.
- Express 5 for new code from day one (legacy stays on 4 until deleted; CC-031 covers the rest).
- `app.js` has no `listen()` so tests use the app in-process.
