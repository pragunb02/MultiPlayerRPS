## Why

The owner's comment rule (ENGINEERING.md §3, item 14: plain words for a new teammate, no semicolons, no dashes as
punctuation, no hyphen bullets, no jargon) was checked by hand only. About a quarter of all comments broke it
(ROADMAP.md §7). A rule that a tool can check should be checked by the tool, and a cleaned folder must not slip back.

## Scope

- In:
  1. Local ESLint rule `classicade/comment-style` (`eslint-rules/`), registered in `eslint.config.js`. It reads every
     comment, skips ESLint, Prettier, coverage and Vitest directives and the shebang, blanks out code spans
     (single and fenced backticks), URLs, JSDoc type braces and `@example` sections, then reports semicolons,
     en and em dashes, spaced hyphens (including the JSDoc `name - description` style), double hyphens used as
     punctuation, hyphen bullets, arrows in prose (`->`, `=>`, `<-`, `-->`, `→`, `←`, `↔`, `⇒`) and the
     denylisted words (idempotent, idempotency, upsert, observer pattern, exactly-once, e.g., i.e., etc.).
     Each problem is reported at its exact place. No autofix.
  2. `scripts/check-comments.mjs`: the same check over CSS comments, part of `npm run lint`.
  3. `scripts/comment-only-diff.mjs <base> [folder ...]`: the proof that a change only touched comments. It compares
     the code tokens (espree, comments left out) of every changed JS file, and the comment-free CSS, before and after.
  4. Rule on (error) for `packages/games`, `packages/shared` and the new `eslint-rules/` and `scripts/` code. Every
     comment in the two packages that broke the rule was reworded (25 files, 86 reported problems).
  5. The scope lives in `eslint-rules/commentStyleScope.mjs`: `COMMENT_STYLE_ON` and `COMMENT_STYLE_SWEEP` with the
     folders of sweep PRs 2 to 6 in ROADMAP order. `eslint.config.js` sets the rule to `off` for those folders.
  6. The rule text in ENGINEERING.md §3 item 14, identical to the docs branch (`cc-docs-reserve-101`) so the two
     merge cleanly in either order.
- Out: the other folders (sweep PRs 2 to 6, CC-126). Checks for "ticket IDs as the only explanation", "JSDoc
  description inside the type braces" and missing JSDoc on exports. They need judgement or type parsing, and are
  left to review.

## Plan / notes

1. **Double hyphen.** Only a double hyphen that is not followed by a letter, digit or hyphen counts. `--color-bg`
   and `--watch` are names, not punctuation. A real dash (`a -- b`, `end --`) is still reported.
2. **Braces.** Brace groups are treated as types only in JSDoc (`/** */`). In a plain comment their content is prose.
3. **Coverage and the real config.** `eslint.config.js` loads the rule modules natively (`require` of ESM, Node 24).
   When a test loads the real config in the Vitest process, that second copy of the same files makes the v8
   coverage report show the rule as untested. So `apps/server/src/architecture.test.js` now runs ESLint in a worker
   thread, and the scope test reads the config in a child process. The assertions of the architecture test are
   unchanged.
4. **New dev dependency** `espree` (already in the tree as ESLint's parser, same version 11.2.0), used by the proof
   script for tokens. No new package is installed.
