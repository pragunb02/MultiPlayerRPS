## Why

Legacy chess trusted the browser for moves and results (SEC-04), echoed moves back to the sender through a shared
per-connection variable (BUG-06), and ran clocks only in the browser (BUG-07) — trivially manipulable and out of sync.

## Scope

- In:
  - **Generic time hooks** in the engine contract: optional `deadline(state)` (when something happens if nobody acts,
    computed from state; 0 = none) + `expire(state, { now })`. `defineEngine` requires both or neither; contract kit
    check 11 proves hooks are pure, integer-valued, change the game at the deadline and stop at the end.
    The room manager's `expireDue({ now })` applies due deadlines for _any_ engine and publishes `room.updated`; the
    gateway broadcasts it; the composition root ticks every second. (Reusable for turn timers / reconnect grace.)
  - **`chessEngine`** (chess.js 1.4.0, latest stable): seeded White; time controls bullet 1+0 … rapid 15+10 (default
    blitz 5+0); clocks start after White's first move, increments applied server-side; actions move (promotion choice
    required) / resign / offer-draw / accept-draw (counter-offer = agreement; moving declines); endings checkmate,
    stalemate, insufficient material, threefold repetition (full-history replay), fifty-move rule, resignation, agreement,
    timeout — a draw if the opponent has no mating material (FIDE 6.9). A move sent after the flag fell loses on time,
    so timeouts are exact; the ticker covers players who stop moving.
- Out: web board (CC-024), Stockfish bot (CC-040), PGN export / replay viewer (CC-041), rematch (CC-037).

## Acceptance criteria

- [x] Passes the shared engine contract kit, including the time-hook check
- [x] Every ending reachable and tested; promotion; draw-offer flow; clocks and increments; exact and ticker timeouts
- [x] Clocks use server time only (a client-supplied clock value is ignored)
- [x] Playable end to end over sockets; timeouts are pushed to both players
