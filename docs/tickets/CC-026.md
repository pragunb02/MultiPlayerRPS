## Scope

- **`Dockerfile`** — multi-stage production image: `node:24-alpine` (matches `.nvmrc`); dependency layers cached
  from the manifests; the web app built inside; dev dependencies pruned; runs as the unprivileged `node` user;
  `HEALTHCHECK` on `/health` (database-aware, as on Render); `NODE_ENV=production`, `WEB_DIST_DIR` preset. Portable
  to any container host — the first step of ADR-005 / CC-028.
- **`docker-compose.yml`** — `mongo:8` with a named volume and a health check, bound to 127.0.0.1; the app waits for
  a healthy database. Runs the production build in `NODE_ENV=development` so cookies work over plain HTTP on
  localhost. Two uses: the whole app (`docker compose up --build` → http://localhost:4000) or MongoDB alone for the
  hot-reload dev servers (`docker compose up mongo`).
- **`.dockerignore`** — no `.git`, `node_modules`, builds, logs, docs or `.env` files in the build context.
- **CI** — a `docker` job builds the image, starts the stack, checks health, a page, the API and the non-root user.

## Verification

- Both containers healthy; `/health` up; pages 200; process user `node`; chess played to mate between two real
  browsers (32/32 images, no console errors); an account created, `docker compose down` + `up`, login works (the
  volume persists); `npm run dev:server` against `docker compose up mongo` connects. Image: Node 24.22, MongoDB 8.3;
  app layers ≈ 45 MB on the Node base.
