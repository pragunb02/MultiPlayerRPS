## Problem

`match-shell.spec.js` › "a win because the opponent left is quiet" failed once in 10 Firefox runs (found in CC-346).
Firefox wrote "[JavaScript Warning: "“localhost” has been classified as a bounce tracker. If it does not receive
user activation within the next 3,600 seconds it will have its state purged."]" to alice's console. The fixtures
fail a test on any console warning they do not know (`fixtures.js`, `checkClean`). Root cause: Firefox's bounce
tracking protection, which is on by default, watches navigations and their timing. Now and then it counts the test
site as a bounce tracker. It is about Firefox and how the test browses, not about the app: every test player is on
the one site, `localhost`, with no third party at all. It did not come back in 20 more runs, so it is rare.

## Fix

Turn the protection off for the test browser through a Firefox pref in `e2e/playwright.config.js`:
`launchOptions.firefoxUserPrefs` sets `privacy.bounceTrackingProtection.mode` to `0` (off). Research: our code passes
launch options for Chromium only (CC-319's certificate flag). Playwright's `firefoxUserPrefs` launch option is its
documented way to set prefs. Firefox's bounce tracking protection is set by `privacy.bounceTrackingProtection.mode`,
where 0 is off (Mozilla's source, `toolkit/components/antitracking/bouncetrackingprotection`), and the pref name is
in the Firefox build Playwright 1.64 uses (`firefox-1555`, its `omni.ja` and `XUL`). Ignoring the message in
`browserNoise.js` instead would leave the protection on, and in a long run it could purge the test site's cookies.

## Acceptance criteria

- **AC-1** Given the Firefox project, when its browser starts, then bounce tracking protection is off
  (`privacy.bounceTrackingProtection.mode` is 0), and no test fails on its "classified as a bounce tracker" warning.

## Test

The warning was 1 in 30 Firefox runs before. It is too rare to show its absence in a few runs. After the change,
Firefox `match-shell.spec.js` and `pass-and-play.spec.js` ran with 6 workers (58 passed, 1 skipped), and the CC-346
Firefox runs (`--repeat-each=10 --workers=1`) passed 20 of 20. CI's Firefox jobs run with the pref from now on.
