## Root cause

The public repository had no security policy, so a researcher had no private way to report a vulnerability. The
owner opened #95 with GitHub's unedited template, which listed made-up versions and placeholder text.

## Research (written before the policy)

1. Today: no SECURITY.md; ADR-023 routes privacy contact through a GitHub issue, which is public and wrong for
   vulnerabilities.
2. Others: GitHub's private vulnerability reporting
   (https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing-information-about-vulnerabilities/privately-reporting-a-security-vulnerability,
   read 2026-10-18) gives a private channel with no email published; the disclose.io safe-harbour terms
   (https://disclose.io, read 2026-10-18) and RFC 9116 security.txt (https://www.rfc-editor.org/rfc/rfc9116) show
   the usual parts: channel, expectations, rules of engagement, scope.
3. For us: a live site with no versions, a single owner, players who may be children (ADR-028) and no budget for a
   bounty. Private reporting through GitHub, short honest response times, rules that protect other players, no
   bounty.

## Verification

Docs only. The owner enables Settings → Code security → Private vulnerability reporting.
