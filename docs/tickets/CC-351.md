## Problem

The clarity audit (CC-348, `docs/design/CLARITY-AUDIT.md`) scored every screen by hand. Nothing stops the next change
from adding a second h1, an icon with no name, a button called "Close" or a Hinglish line with "aap".

**Root cause.** The rules lived only in the design contract and the review lens (CC-316). The one rule with a test,
"tum, never aap", had nine copies, one per copy module, each with its own regex (four different ones), and none read
the Hinglish written inline in a page, such as `PrivacySettings.jsx`.

## Fix

Four of the audit's six automatic checks. A2 (How to play, CC-349) and A4 (raw server words, CC-350) are not here.

- **A1 and A3, `e2e/clarity.spec.js`.** Every route a visitor, a guest, a new account and the seeded owner can open,
  the dead ends, and every match state of `e2e/matchStates.js` (both players' screens, and each game against the
  computer), on the desktop and the phone. On each settled screen: exactly one h1 (it waits up to 10 s for one, then
  checks it stays one); every visible control has an accessible name that is not a bare "Close", "X", "OK" or
  "Submit"; a control with no visible letter or digit must be on `CONTROLS_WITHOUT_WORDS`. That list may only shrink:
  a test fails when it has more lines than `RECORDED_SIZE`, and a comment says to lower the number, never raise it.
  A self-test on a made-up page proves each check catches what it looks for.
- **A6, the same spec, advisory.** A button's words start with a verb, or the button is on a short list of buttons
  that name a thing (a hand, a computer level, a chess move). Others are written as a warning on the test (an
  annotation in the report and a `warning:` line in the output). It never fails.
- **A5, `apps/web/src/copy.hinglish.test.js`.** One test for the whole app: every source file under `apps/web/src`,
  comments removed, must not contain `aap`, `aapka`, `aapke`, `aapki`, `aapko`, `aapne`, `kijiye`, `karein`,
  `dijiye`, or a polite question ending in `ein?` or `ijiye?`. Every copy module's Hinglish lines, made at run time
  with names filled in, are checked the same way, and each module that speaks to the player must use "tum" at least
  once. The nine copies are deleted. Each place now has a comment pointing to the shared test, and the other checks
  those tests made (both languages present, "Tumhari pehchaan nahi.") stay as tests of their own.

**Research.**

- **Our code today.** `e2e/accessibility.spec.js` runs axe, whose `page-has-heading-one` rule checks that there is at
  least one h1, not exactly one. Its `button-name` and `link-name` rules check that a name exists, not what it says.
  So A1's "exactly one" and A3's "not a bare Close" need checks of their own. The pop-up list in CONTRACT section 5
  (`eslint-rules/popupContract.mjs`) is the model for a list that may only shrink.
- **Accessible names.** The spec reads a control's name the way the accessible name algorithm does, in short
  (aria-labelledby, then aria-label, then the text inside with image alts, then title;
  [W3C, Accessible Name and Description Computation 1.2](https://www.w3.org/TR/accname-1.2/)). Playwright has no API
  that returns a name, only `toHaveAccessibleName` for a name you already know, and the spec must run on Firefox and
  WebKit too, so it does not use Chromium's accessibility tree.
- **Other products.** GOV.UK's button guidance asks for text "describing the action it performs"
  ([GOV.UK Design System, Button](https://design-system.service.gov.uk/components/button/)), the source the audit
  quotes for C2. A verb test cannot tell
  whether the words are clear, so A6 stays advisory, as the audit proposed, and the design lens keeps that job.
- **Best for ClassiCade.** Checks in the browser on real screens, reusing `matchStates.js` so every state is built the
  way the match-shell tests build it, plus one source scan for the Hinglish rule. That catches the inline lines and
  templates that a test of each copy module never sees.

## What the checks found today (2026-10-22, desktop and phone, 102 tests, all pass)

- **A1.** Every settled screen has exactly one h1: 23 visitor routes, 8 guest and account pages, 12 owner console
  pages, and 46 match and computer states on both screens. The loading states the audit found without one (CL-79,
  CL-88) are not settled screens, so the check waits past them.
- **A3.** Every control has a name. No bare "Close" was on a screen the walk reaches: the request banner's "Close"
  (CL-36) shows only when a rematch expires unanswered, after a minute. 12 kinds of control show no word. They and
  four more found in the code make the starting list of **16**: the logo, the speaker, the sound gear and the
  phone's menu (CL-03, CL-04), the chess move list's four steps (CL-41), the promotion pieces (CL-42), the chess
  squares and Tic-Tac-Toe cells, and four dismiss × (`save.dismiss`, `streak.dismiss`, `request.dismiss`,
  `toast.dismiss`). Two of them are named only "Close" and carry `bareName: "Close"` until fixed: `request.dismiss`
  (CL-36) and `toast.dismiss`, which `FriendRequestToasts.jsx` and `SiteRequests.jsx` name only "Close" (found reading
  the code, fixed the same way as CL-36).
- **A5.** Passes. No Hinglish line in `apps/web/src` uses "aap" or a polite form.
- **A6, advisory.** Six buttons start with no verb:
  - "Feedback" (`header.feedback`, `footer.feedback`), on every page;
  - "New opponent" (`room.new_opponent`, `request.new_opponent`), on every result;
  - "Not now" (`site_request.decline`), the request pop-up on another page (CL-89 renames it);
  - "How we keep it fair" (`rps.fairness`).

## Acceptance criteria

- **AC-1** Given any route or match state the spec walks, on the desktop or the phone, when it settles, then it has
  exactly one h1.
- **AC-2** Given a visible control, then it has a name that is not a bare "Close", "X", "OK" or "Submit", unless its
  line on `CONTROLS_WITHOUT_WORDS` allows that name; and a control with no visible letter or digit is on that list.
- **AC-3** Given `CONTROLS_WITHOUT_WORDS`, when it has more lines than `RECORDED_SIZE` (16), then the spec fails.
- **AC-4** Given any source file or copy module in `apps/web/src`, when a Hinglish line uses "aap" or a polite form,
  then `copy.hinglish.test.js` fails and names the file and line. The nine copies of the check are gone.
- **AC-5** Given a button that starts with no verb and is not on `BUTTON_WORDS`, then the spec writes a warning and
  does not fail.

## Test

`e2e/clarity.spec.js` (102 tests, `--workers=1`, desktop and mobile, about 5.6 minutes). Its self-test feeds a page
with two h1, a bare "Close", an unlisted icon and a nameless link, and checks each is reported. Before the allowlist
was filled, the walk failed on every icon-only control, which is how the list was made.
`apps/web/src/copy.hinglish.test.js`: a probe file with an inline `<span lang="hi-Latn">Aapka turn</span>` made it fail
with the file and line, and a comment with "aap" did not.
