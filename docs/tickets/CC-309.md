### 2. How other projects handle the same problems

1. Vitest merges the coverage of all projects into one istanbul map, and istanbul merges functions by their
   source location (`istanbul-lib-coverage` `FileCoverage.merge`, keyed by `decl`/`loc`). Two different source maps
   for one file give two entries for the same function. Vitest's own docs say the transform decides the map
   ("Source maps can change based on projectName and transform mode", `@vitest/coverage-v8` provider, v5.0.5).
2. `@vitejs/plugin-react` 6 defaults `include` to `/\.[tj]sx?$/` and passes it to Vite as `oxc.jsxRefreshInclude`.
   Vite 8's `vite:oxc` plugin transforms any id that filter matches (`node_modules/vite/dist/node/chunks/node.js`,
   `oxcPlugin`), so every plain `.js` file outside `node_modules` is reprinted by oxc in that project. The plugin's
   README documents `include` for exactly this: limiting which files it touches.
3. Playwright's guidance for shared state: a test must not depend on what other tests did before it
   (https://playwright.dev/docs/best-practices#make-tests-as-isolated-as-possible, read 2026-10-20).

### 3. What is best for ClassiCade

Fix each cause where it is, keep every check as strict as it was, and add no retries or longer timeouts.

## Root causes

### A. Coverage gate (latest run): one file counted twice

`packages/shared/src/build.js` (CC-303, #127) showed 66.66 % of functions, lines 22-53, although its own 21 tests
call every function. The web project's React plugin had oxc reprint every `.js` file, including the shared
packages the web tests load through `@classicade/shared`. oxc's source map is token-level; the node project keeps
the file as written with a fine map. For arrow functions the two maps put the start at different columns
(`parseCommit` at 21:27 in node, 21:13 in web), so the merged report had six functions instead of four, and the two
web copies were never called. Function declarations (`calendarVersion`, `isCalendarVersionOf`) map the same in
both and merged. Reproduced locally with `build.test.js` plus one web test (`paths.test.js`): 4/6 functions. This
is the same effect the CC-253 builder met with engine functions, and why the branch floor needed slack for
"shared files loaded by both projects" (CC-084).

Fix: the web project's plugin is `react({ include: /\.jsx$/ })`. JSX lives only in `.jsx` files (checked: no
`.js` file under `apps/web/src` has JSX), so `.js` files are no longer reprinted and both projects map them the
same. Same pair of tests after: 4/4. Full `npm run test:coverage` after: 375 files pass, functions 100 %,
statements 99.96 %, branches 99.76 % (from 99.39 %).
