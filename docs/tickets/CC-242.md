## Research (written before any code)

To be written by the builder before any code: how our code does it today, how other products do it (with sources
and dates), and what is best for ClassiCade.

## Why

Rooms keep only their current state (CC-101), and finished games keep their moves (`matches.log`). What happened around a game is lost: who joined, left, dropped and came back, forfeits, rematch asks and answers, and why a room closed beyond the 24 hour closed record. Support, disputes about forfeits and the analytics console need it.

## Scope

- In: an append-only `room_events` collection written by the room component on every transition, with a 30 day TTL index; the reasons from `ROOM_CLOSE_REASONS`; no IP or user agent.
- Out: showing the history to players; analytics charts (CC-244, CC-177).

## Acceptance criteria

- [ ] Every room transition writes exactly one event, tested against the state machine
- [ ] Events expire after 30 days
- [ ] Writing an event never blocks or fails a player's action
- [ ] Tests cover the change
- [ ] `npm run lint`, `npm run format:check`, `npm test` pass
- [ ] Docs updated (BACKLOG status, KNOWN_ISSUES, PROGRESS)
