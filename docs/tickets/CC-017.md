## Why

The legacy app counted every RPS round as a game (BUG-02), counted chess games on _join_ (BUG-05), and sent level-ups
to a socket map that no client ever registered with (BUG-08). Progress must come only from completed, recorded matches,
exactly once, and reach the player.

## Scope

- In:
  - **Shared rules** (`@classicade/shared`): `XP_AWARDS` (win 30, draw 15, loss 10, forfeit 0), `xpForLevel`/`levelForXp`
    (1 → 0, 2 → 50, 3 → 150, 4 → 300 … max 100) — the web app shows exactly what the server awards.
  - **Persistence**: `player_progress` (MongoDB) with an **atomic exactly-once** `applyMatchOnce` (conditional upsert +
    recent-match window; explicit retry when two matches create a new player's document at once); in-memory double;
    shared DAO contract; concurrency tests.
  - **Data**: progress accessor (new players = zero progress; before/after totals).
  - **Domain**: progression component — result per player (win/draw/loss/forfeit from the match log), XP, level-up
    detection, `progression.updated` events, level details for progress bars.
  - **Pipeline**: game finished → record match → apply progression, as background tasks (`utils/backgroundTasks`)
    that shutdown drains; progression never runs if recording failed.
  - **Service**: `GET /api/progress`; sockets join a per-player channel; `progress:updated` pushed to every tab.
- Out: guest → account merge (CC-032), ratings (CC-042), achievements (CC-054), leaderboards (CC-053), bot-game rules (CC-038).

## Acceptance criteria

- [x] XP only from recorded matches, once per match per player — also under concurrency
- [x] Forfeit (leaving a game in progress) earns 0 XP but counts as a loss
- [x] Level-ups reach the player's browser, on every open tab
- [x] Tests, lint, format, coverage, audit pass; ran for real

## Notes

- Found by reasoning, guarded by a test: concurrent first matches for a new player could collide on the upsert and be
  treated as "already applied". MongoDB retries such upserts itself; the DAO now handles it explicitly too.
- The 5-run check caught a flaky end-to-end test (a listener could catch the previous push); fixed by awaiting the first
  push. 20/20 isolated runs and 5/5 full-suite runs green afterwards.

## Verification

- 553 tests (5 consecutive green runs) incl. MongoDB integration (XP stored after a socket game) and concurrency tests.
- Live: two best-of-1 wins → 30 → 60 XP with a pushed level-up; a forfeit gave the leaver 0 XP; `GET /api/progress` correct.
