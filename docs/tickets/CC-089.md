## Why

Short, achievable goals that change every day are the main "come back tomorrow" loop in Fortnite, Clash Royale,
Brawl Stars and Duolingo. Three quests a day with small XP rewards, a sweep bonus and a visible midnight countdown.

## Scope

- In:
  - Shared catalog `packages/shared/src/quests.js`: 12 quests in 3 slots (play, win, game), what each counts
    (`play`, `win`, `distinct-games`, `wins-in-a-row`), `DAILY_SWEEP_BONUS_XP = 30`.
  - Pure `questsFor({ playerId, day })`: FNV-1a 32 of `"<playerId>:<day>"`, then per slot (play, win, game)
    `index = seed % pool.length`, `seed = mulberry32 step` — pinned outputs in `questsFor.test.js`.
  - Pure `questProgress.js`: the day's snapshot (`newQuestDay`) and `applyMatchToQuests` (progress capped at the
    target, `completedAt` at the match time, sweep when all three are done).
  - Snapshot in `player_quests` (`{playerId, day}` unique, TTL on `expiresAt` = day start + 8 days) written on the
    first read or first counted match of the day; the stored snapshot (with names and rules) is the truth for that
    day, so a catalog change during a deploy never reshuffles quests.
  - Bonus XP through `progressionComponent.awardBonus({ playerId, displayName, key, xp, at })` →
    `progressAccessor.applyAwardOnce`, exactly once per `quest:<day>:<questId>` / `quest:<day>:sweep`.
  - HTTP `GET /api/quests`; socket push `quests:updated` (only for today's quests) and `progress:updated` with
    `source: "quest"`.
  - Web: `useQuests`, `useCountdown` (once a minute, reloads at reset, never loops when this device's clock is
    ahead), `DailyQuests` (full on the profile's Player console; `compact` on the home page when there is a
    session), "Quest complete! +40 XP" / "Daily sweep! +30 XP" toasts.
- Out: quest art (CC-087), weekly quests, rerolls.

## Acceptance criteria

- [x] Quests are deterministic for a (player, day) pair and stable once stored (catalog changes don't reshuffle).
- [x] Bonuses are awarded exactly once, even when the same match is applied twice.
- [x] UTC midnight rollover works with an injected `now` (23:59:59.999 vs 00:00 tested on server and web).
- [x] A player's own forfeit never moves a quest; a draw keeps a "wins in a row" run, a loss ends it.
- [x] UI: loading, error with retry, "Play your first match to start quests", progress `<progress>` + "1/2",
      completed with a check and "+30 XP", sweep row, "Resets in 5h 12m" (`aria-live="off"`).
- [x] Tests: pure, component, DAO contracts, HTTP + socket, MongoDB integration, Playwright.

## Plan / notes

- The brief said quest XP is capped at 170 a day; the catalog's real maximum is **150** (richest of each slot:
  30 + 40 + 50, plus the 30 sweep). Pinned in `packages/shared/src/gamification.test.js`. The catalog numbers follow
  the brief; only the stated total was off.
- Quest progress for a match is applied to the match's own UTC day. A match that ends at 23:59:58 and is recorded
  after midnight still counts for the day it was played; its push is skipped because today's quests didn't change.
- Guests' quest days are deleted on transfer (ADR-014): the bonus XP already moved with progress; the account keeps
  its own day.
