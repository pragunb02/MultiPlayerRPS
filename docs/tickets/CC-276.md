## Root cause

`.github/actions/backup-tools/action.yml` runs under `set -euo pipefail` and printed the version with
`mongodump --version | head -n 1`. `head` exits after the first line; if `mongodump` is still writing, it gets SIGPIPE
and exits 141, and pipefail turns that into a failed step. Whether it happens depends on timing, so the required
"Backup round trip" check (and the nightly backup, which uses the same action) failed at random (run 39104477990).

## Research

Bash's `pipefail` reports the last non-zero status in a pipeline, including a writer killed by SIGPIPE (Bash manual,
"Pipelines", read 2026-10-18). The usual fixes are a reader that consumes all input (`sed -n 1p`) or not piping.

## Verification

The step now prints the first line with `sed -n 1p`, which reads to the end, so the writer never gets SIGPIPE.
The backup round trip check passes on this PR.
