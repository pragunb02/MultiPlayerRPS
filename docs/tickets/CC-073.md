## Why

The owner asked for future-proof, well-architected code with proper unit tests and the latest stable dependencies.
Standards only hold if they are written down **and** checked by tools, before the bulk of new code is written.

## Scope

- In:
  - [ENGINEERING.md](../ENGINEERING.md): five-layer server architecture, design principles, patterns and where they apply,
    extension points, coding standards, testing standards, dependency policy, definition of done.
  - ESLint layer rules (`no-restricted-imports` per layer) and engine purity rules; `architecture.test.js` proves they fire.
  - Coverage gates (`npm run test:coverage`, v8): 80 % overall, 90 % for `packages/games`.
  - Move CC-011 HTTP code into `service/http/`; make the shutdown handler injectable and fully tested.
  - Dependency policy applied: legacy same-major updates, `connect-mongodb-session` 2 → 5, nodemon → `node --watch`, audit to 0.
  - Deprecation warning for the `MONGO_URI_PRODUCTION` fallback (removal: CC-074).
- Out: CI wiring of the gates (CC-027), Dependabot (CC-031), logger/typed errors (CC-012).

## Acceptance criteria

- [x] Guidelines cover architecture, principles, patterns, extension points, coding, testing, dependencies
- [x] Importing across layers illegally fails `npm run lint` (proved by tests)
- [x] Engine purity violations (`Math.random`, `Date.now`, `node:*`, timers) fail lint (proved by tests)
- [x] `npm run test:coverage` enforces floors and passes
- [x] `npm audit` reports 0 vulnerabilities
- [x] Legacy auth/session/RPS flows still work after dependency changes

## Notes

- Guidelines are written for this codebase in our own words; no external/internal documents are copied into the (public) repo.
