## Problem

ADR-051 put Hinglish first and English under it on every line of feeling, and the owner kept it. But nothing says
how the two lines look. In the Feedback dialog, on the friends page, on the challenge screens and in the sign-up
helper, the Hinglish is bold at full size and the English is full size too, so each message is two loud lines; the
dialog title is in two languages; "Appear offline" has four paragraphs; and three copy modules use two different
shapes (`{ hi, en }` and `{ hinglish, english }`) with three different components (AUDIT-2026-10, RC-8; findings
`feedback-dialog 390-light`, `friends-empty 390-dark`, `challenge-missing 390-light`, `signup-error 390-dark`).

## Job to be done

When I read a message, I want one clear line in the language I speak with a quieter translation under it, so I get
it at a glance and the screen does not shout twice.

## Appetite

S (up to 2 agent-hours) for the component, the shape and the check, plus the copy on the four named screens. **Cut
line:** the report dialog and the age helper move to the pattern in a follow-up small PR. The component, the one
shape, the type roles, the caps and the check are never cut.

## Proposed solution

### The pattern

A **bilingual pair** is one message in two lines:

| Line            | Language                 | Type role                        | Weight             | Colour                                         | `lang`    |
| --------------- | ------------------------ | -------------------------------- | ------------------ | ---------------------------------------------- | --------- |
| **Main line**   | Hinglish (ADR-051 order) | `--type-body`, `--leading-body`  | `--weight-medium`  | `--color-text`                                 | `hi-Latn` |
| **Second line** | English                  | `--type-label`, `--leading-body` | `--weight-regular` | `--color-text-muted` (5.37:1 on the CC-329 bg) | `en`      |

A `size="sm"` pair (inside a card, a list row or a toast-sized space) steps both down one role: main
`--type-label` medium, second `--type-caption` regular. The gap between the lines is `--space-1`. The two lines are
one paragraph to a screen reader, in that order; nothing is hidden.

### Where it is used, and where it is not

1. **Bilingual pairs** for sentences of feeling or explanation: outcome lines, empty states, dialog bodies,
   challenge and friend messages, safety notes, greetings (CC-328), share text previews.
2. **One language (English)** for controls and labels: buttons (as today), titles of pages, sections and dialogs,
   tabs, field labels and hints, badges, toasts and banners. A title is never a pair.
3. **The English line is a translation, not more information.** Extra detail goes in a field hint or behind a
   "Why?" disclosure (`useExplanation`), never in a longer second line.

### Caps

| Where              | At most                                                                 |
| ------------------ | ----------------------------------------------------------------------- |
| Main line          | 80 characters, one sentence (two lines at 390 px in `--type-body`)      |
| Second line        | 100 characters, one sentence                                            |
| Pairs per region   | Dialog body 2, empty state 1, card 1, banner 0 (one line only), toast 0 |
| A pair with a name | Measured with a 20 character name, the longest sign-up allows (CC-256)  |

CONTRACT.md's section on copy limits (one line per language, button 3 words, dialog title 6 words) stays; these caps
add the numbers for the pair. A unit test measures every static pair in the copy modules and every template pair
with a 20 character name, so a too-long line fails CI (the contract's "checked in review" now has a check, because
the pair is data).

### One shape, one component

- **Shape:** `Readonly<{ hi: string, en: string }>`, frozen, everywhere. `feedbackText.js`'s `{ hinglish, english }`
  and `outcomeLine.js`'s become `{ hi, en }` (the outcome line is converted by CC-327, which owns `outcomeLine.js` and
  `MatchFrame.jsx`; until then `Bilingual` accepts the old shape through one adapter, removed by CC-327).
- **Component:** `components/Bilingual/Bilingual.jsx` (moved from `components/Profile/Bilingual.jsx`), props `copy`,
  `size` (`md` or `sm`), `as` (`p`, `span` or `div`). Its CSS module holds the two roles above. The Profile, Friends,
  Challenges and Feedback modules drop their own `hinglish` and `english` classes.
- **Design rules** are written in a new `docs/design/COPY.md` (this pattern, the caps, examples). CC-327 links it from
  CONTRACT.md's copy section in Wave 2b, so this ticket does not edit CONTRACT.md while CC-328 does.

## Rabbit holes

- **Counting characters in Hinglish.** Plain `length` of the string; no word heuristics.
- **Template lines with names.** Measured once with the 20 character placeholder; no per-name runtime check.
- **`lang="hi-Latn"`.** Kept as today (CC-034); screen reader behaviour is unchanged by this ticket.

## Research (written before any code)

1. **How our code does it today.** `components/Profile/Bilingual.jsx` (`{ hi, en }`, a `hinglish` and an `english`
   class), `friendsCopy.js` and `challengeCopy.js` (`{ hi, en }`), `feedbackText.js` and `outcomeLine.js`
   (`{ hinglish, english }`), `MatchFrame.jsx` drawing the outcome pair with its own spans, and four CSS modules
   styling the lines each their own way.
2. **How others do it.** Material 3's type scale (m3.material.io, general knowledge, high confidence) pairs a body
   line with a smaller supporting line in a lower-emphasis colour; bilingual signage practice (for example the
   Indian Railways station boards, general knowledge, high confidence) gives one language the larger size and the
   second the smaller, never both equal. WCAG 3.1.2 asks for `lang` on parts in another language.
3. **What is best for ClassiCade.** Keep the owner's Hinglish-first voice and make it calm: one leading line, one
   quiet translation, short enough to read at a glance on a phone, with a machine check so it stays that way.
