## Why

Unit and integration tests can't see what a person sees: the address bar, the Back button, the browser console, the
network tab. The owner asked for tests that act like different kinds of people and check that nothing leaks and
nobody has a bad experience.

## Scope

- `e2e/` workspace: Playwright, Chromium on desktop and a mobile viewport; `e2e/server.mjs` starts the real composition
  root with the **production** configuration, the built web app and an in-memory MongoDB seeded with a legacy player.
- The `players` fixture records everything each browser sees and fails the test on: console errors/warnings, page
  errors, CSP violations, unexpected failed requests; passwords, emails or the session id in any URL; a session cookie
  that isn't `HttpOnly`, `Secure`, `SameSite=Lax`; anything in `localStorage`/`sessionStorage`.
- Personas: **visitor** (no session until they play, titles, Back, old links, 404, profile → login), **guests** (RPS
  without seeing the other's pending choice in DOM or WebSocket frames; leave/forfeit; sign up from a room),
  **account holder** (sign up/out/in with `next`, account pages skipped when signed in, generic wrong-password answer,
  taken username on the right field), **legacy player** (old password works; their email can't be taken), **attacker**
  (crafted `next` links, markup in URLs, cross-site writes, error bodies without internals, security headers).

## Found and fixed

- **CC-082** — every first visit logged a red `401 (Unauthorized)` in the console: the "do I have a session?" probe
  treated "not yet" as an error. `GET /api/session` now answers 200 `{ authenticated: false }`; 401 stays for a corrupt
  session.
- **Socket reconnect race** — pages asking for a guest session twice (the room page re-asks when the session state
  changes) created it twice and reconnected a socket that was still connecting ("WebSocket is closed before the
  connection is established"). One in-flight guest request is shared; the same identity never reconnects.
- **CC-083** — a guest who signed up from a room came back seated against their own old guest seat; the game started
  against themselves and their friend couldn't join. On sign-in, rooms now hand the guest's seats (waiting and running
  games, host role, game state and log) to the account and tell everyone in them. `renamePlayer` in
  `@classicade/games` plus a new engine-contract check: every engine must finish a game after a mid-game rename.
- The composition root accepts rate limits (`startServer({ limits })`), because every browser test shares one IP;
  production uses the defaults.

## Verification

- 34 browser tests, stable across 4 consecutive runs (~8 s). 833 unit/integration tests (new: session probe, guest
  de-duplication, seat transfer in the room domain and over HTTP + WebSocket, the rename contract check on RPS,
  Tic-Tac-Toe, Chess and the reference engine).
