## Why

The owner played a full game in silence. Every game site people know (chess.com, lichess) gives each move, capture
and result a short sound, and that sound is what tells a player in another window that something happened. Players
also need a quick way to turn it off.

## Scope

- In: a sound system in `apps/web/src/lib/sound` (catalogue, synthesised notes, player, saved preference), sounds
  derived from room updates for every game through the client game registry, sounds for rewards (achievement, quest,
  level up), a subtle click for the app's buttons, the chess low time tick, and a sound switch with a volume slider in
  the header.
- Out: per-game sound themes, a sound settings page, sounds for spectators' results.

## Acceptance criteria

- [x] Catalogue: move, capture, check, castle, game start, your turn, win, loss, draw, low time tick, notification,
      achievement unlocked, level up, button click, plus the Tic-Tac-Toe mark and line and the Rock Paper Scissors
      reveal and round won or lost.
- [x] Each game in `games/registry.js` has a pure `soundsFor(previous, next, you)`. `games/roomUpdates.js` adds the
      room's own sounds (start, result, request chime, your turn in a background tab). A reload makes no sound.
- [x] Audio starts only during a user gesture and never throws (no Web Audio, refused resume, broken node).
- [x] Header switch named "Sound on" or "Sound off", volume slider "Volume", choice kept across reloads.
- [x] Default: sound on at volume 0.6.
- [x] Unit tests for every `soundsFor`, the player (fake AudioContext), the preferences, the hooks and the header
      control. Browser test for the switch surviving a reload.

## ADR-018 (proposed): sounds are synthesised in the browser, and one preference may live in localStorage

The number is provisional and is fixed when the record moves to DECISIONS.md.

Context. We need about twenty short sounds. Audio files need a licence check, add downloads, and would need the CSP
to allow media. Browsers also refuse to start audio before the person has touched the page, and Chrome logs a
console warning when a page tries.

Decision.

1. Every sound is a few notes built with the Web Audio API (`OscillatorNode` and `GainNode`) from a recipe in
   `lib/sound/sounds.js`. There are no audio files, nothing to license, nothing to download, and no CSP change.
2. The audio context is created only inside a user gesture (`navigator.userActivation.isActive`). Before that `play`
   does nothing. The player is created in `main.jsx`, injected through the services context like the API and socket
   clients, and tests use `fakeSound()`, which records what would have played.
3. Sounds are worked out from two RoomViews (before and after an update) by pure functions, so they come out the same
   for every kind of update (a push, the answer to your own move, a rematch) and need no extra server events.
4. Sound settings are a preference of this browser, not of the account, so they live in `localStorage` under the
   single key `cc.sound` with the exact shape `{"muted":boolean,"volume":number}`. The browser tests used to demand
   that web storage is empty. They now allow exactly the keys in `STORAGE_ALLOWLIST` (`e2e/fixtures.js`), each with a
   checker for its value, so nothing identifying a player or a game can slip into storage that page scripts can read
   and that outlives the session.

Consequences. Sounds are tuned in code (gain values and wave shapes, with a unit test that keeps every note soft and
short). Changing a sound is a code change. A browser without Web Audio stays silent.

Why not a library (Howler, Tone.js): both are built for playing files or music and would add weight for what is
about two hundred lines.

## Plan / notes

1. Loudness: the slider is squared before use, because ears hear loudness roughly that way, and multiplied by a
   master level of 0.8. Square and sawtooth waves stay under a gain of 0.1 because they sound much louder.
2. Sounds asked for together are spaced 0.12 s apart so a capture and the win sound do not land on top of each other.
3. The low time tick plays once per displayed second while your own clock runs under ten seconds.
4. Reduced motion does not mute sound. Sound has its own switch, as the brief asks.

## Verification

Unit tests: `lib/sound/*.test.js`, `games/*Alerts.test.js`, `games/roomUpdates.test.js`, `hooks/useSound.test.jsx`,
`pages/RoomPage/RoomPage.alerts.test.jsx` (header control, move and start sounds, background tab sound), and the
reward toasts. Browser test: `e2e/requests.spec.js` "sound switch" (desktop and mobile). The fixture checks every
test's storage against the allowlist.
