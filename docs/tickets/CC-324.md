## Problem

The October audit ([AUDIT-2026-10.md](../design/AUDIT-2026-10.md)) found the header breaking on every page: the
compact header switched on only under 40rem, with no plan for 641 to 1100 px, so all 77 states scrolled sideways at
768 px (the header was 813 px wide for a visitor and 1203 px for the owner), a guest's name wrapped one letter per
line, the volume slider took the widest place in the row, the phone menu was a loose pile with no groups, and
"Leaderboards" lost its current state on every board but `/overall`. Along the way it found four more bugs in
screens that exist: a visitor's `/friends` said "Loading…" for ever, the leaderboard's "YOU" tag stacked one letter
per line at 390 px, the Inbox button's name did not contain its visible text (axe `label-content-name-mismatch`,
serious), and the owner console failed axe `heading-order` on six pages.

## Job to be done

When a player opens ClassiCade on any phone, tablet or laptop, they want the header to fit, to show where they
are and to put every control one or two presses away, so they can get to a game without fighting the page.

## Appetite

M (up to 6 agent-hours). **Cut line:** the grouped menu's two-column tablet layout and the motion polish go first;
no-scroll at every width and the five bugs stay.

## Proposed solution

Built. Two breakpoints, read in render (`useMediaQuery`, `components/Layout/headerLayout.js`), so each control is in
the page once:

| Width          | Row                                                                                                      | Menu                                              |
| -------------- | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| under 40rem    | logo glyph, Inbox, Menu                                                                                  | Play (Games, Leaderboards), Social, You, Settings |
| 40rem to 64rem | wordmark, Games, Leaderboards, Inbox, Menu                                                               | Social, You, Settings (in columns)                |
| 64rem and over | wordmark, Games, Leaderboards, Console (admin), Inbox, sound pill, level, account menu, Log in / Sign up | none                                              |

- **Sound pill** (wide): the speaker stays one press to mute; a chevron opens a small panel with the volume slider
  and Sound settings. In the menu the three sound controls sit in one row.
- **Account menu** (wide): the player's name, cut with an ellipsis at 11rem, with the whole name in its text and
  title; it opens Profile, Friends, Feedback and Log out. It is a disclosure, not an ARIA menu: Tab moves through it,
  Escape closes it and returns the focus.
- **Current item**: `sectionOf(pathname)` puts every board under Leaderboards and every lobby, room, daily puzzle and
  challenge under Games. The current item gets the soft pill, the inset bar and a new subtle halo, `--glow-current`.
- **Motion**: CSS only, ADR-075's simple tier: `transform`, `opacity`, `box-shadow` and colour transitions on the
  `--duration-*` tokens, `@starting-style` entrances for the panels, no keyframes, so reduced motion zeroes all of it.
- **Inbox badge**: the count pill stays; the button's name is now its own words, "Inbox 1", then "waiting".
- **Feedback dialog off the first route** (asked by CC-322): `LazyFeedbackDialog` loads the dialog's chunk (about
  2.5 kB gzip with its CSS) 300 ms after the first page, or at once on a press, and draws it as soon as it is there.
  Not `React.lazy`: a suspended component was revealed about 800 ms after its code arrived, too slow for the match
  shell's 100 ms press rule. Test: `LazyFeedbackDialog.test.jsx`, and `match-shell.spec.js` presses Feedback.

## Non-goals

- Shared components (CC-323: EmptyState, Card, Button variants). A minimal local empty state on `/friends` is
  marked `TODO(CC-323)`.
- Route lazy-loading and the bundle (CC-322), the match stage, the footer's tap targets, the inbox panel's own design
  (CC-315 NoticeCentre).

## Rabbit holes

- Duplicated links hidden by CSS (they would show twice to tests and to anything without CSS). Avoided by choosing
  the layout in render.
- An ARIA `menu` with arrow keys for the account menu. A disclosure is simpler and what the APG recommends for site
  navigation.

- **AC-3** Given a wide screen, the volume is in the sound pill's panel and Log out, Profile, Friends and Feedback
  are in the account menu, both opened by Enter and closed by Escape. Tests: `HeaderMenu.test.jsx` › "the wide
  header" block; `e2e/header.spec.js` › "opens the sound options and the account menu from the keyboard…"
- **AC-4** Given `/leaderboards/weekly` or a game's board, Leaderboards is the current page, on both layouts. Tests:
  `HeaderMenu.test.jsx` › "marks Leaderboards as the current page on %s"; `e2e/header.spec.js` › "marks Leaderboards

- **Defaults:** unchanged.

## Alternatives considered

- **CSS-only switching with every control in the page once** (the old approach): at 320 px the game links cannot
  share the row with the inbox and the menu, so they would need a second copy in the menu, shown twice to tests,
  to search and to anything without CSS.
- **A bottom tab bar on phones**: the common mobile game pattern, but a fixed bar is a new pop-up type under
  CONTRACT.md §5, and it takes height from the boards. Left for a later design pass.
- **An ARIA menu with arrow keys**: the APG's disclosure pattern fits site navigation better and needs no roving
  focus.

## Research (written before any code)

1. **Our code today.** `Layout.jsx` drew every control once and `Layout.module.css` hid or showed them at one
   breakpoint, `max-width: 40rem` (CC-259). Between 641 px and about 1100 px nothing gave way: the row was mute,
   volume slider, settings, level chip, name, Log in, Sign up and Feedback after the links. The menu panel was the
   same row wrapped. `NavLink` marked Leaderboards on `/leaderboards/overall` only. Measured on main with Playwright
   at 4993: 813 px of page at 768 for a visitor, 1203 px at 768 and at 1024 for the owner, header 214 px tall.
2. **Other products** (read 2026-10-21). Chess.com and Lichess put the account (name and avatar) behind one menu at
   the right of the bar and keep the game links visible on desktop; on phones both use one menu button with grouped
   rows. The WAI-ARIA Authoring Practices "Disclosure Navigation Menu" example
   (w3.org/WAI/ARIA/apg/patterns/disclosure/examples/disclosure-navigation/) recommends disclosures, not `role=menu`,
   for site navigation. WCAG 2.5.3 Label in Name requires the visible text to start the accessible name. GOV.UK's
   header component collapses to a menu button below its tablet breakpoint and marks the current section, not only
   the exact page. Material 3's navigation guidance groups destinations and keeps one current indicator.
3. **Best for ClassiCade.** Most players are on mid-range Android phones (BRD), so the phone row stays one line
   with the inbox always visible, and everything else is one press away in labelled groups with 44 px rows. Tablets
   keep the two game links in the row. From 64rem the row has room for the game links and the controls a player
   uses mid-session (mute, level, inbox), and the rest goes under the name. Effects stay in ADR-075's simple tier
   (CSS, tokens, no keyframes), within the CC-314 tokens and the `--layer-menu` layer, so no contract change.
