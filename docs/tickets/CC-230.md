## Research (written before any code)

### 1. How our code does it today

1. **Art drawn in code.** Almost all of our art is hand-drawn SVG in React components under `apps/web/src/art/`
   (ADR-012): the logo and glyph, the home hero, the game tiles, the RPS hands, the Tic-Tac-Toe marks, medals,
   badges, achievement icons, confetti and the 404 and empty state illustrations. It was drawn for ClassiCade in
   CC-087 and later tickets, and nothing records who owns it or under which licence.
2. **Asset files.** `apps/web` holds 18 asset files today:
   1. `public/favicon.svg` and `public/favicon-turn.svg`: our glyph, copied from `LogoMark` (CC-087, CC-104).
   2. `public/og/*.png` (4): link preview cards, screenshots of our own art made by `apps/web/og/render.mjs`
      (CC-047).
   3. `public/pieces/*.png` (12): the chess pieces. Their only record is `public/pieces/LICENSE.md`, which says
      "Cburnett set from Wikimedia Commons, CC BY-SA 3.0". They came into the repo on 2024-06-27 in the legacy app
      as `client/public/img/chesspieces/wikipedia/*.png`, the PNG renders that chessboard.js ships as its
      "wikipedia" theme, and were moved to `apps/web/public/pieces` in CC-024. Who made the PNG renders is not
      recorded. A faithful render of a drawing adds no new copyright, so the licence is Cburnett's.
3. **Sounds.** None are files. `apps/web/src/lib/sound/sounds.js` synthesises every sound from a few notes with the
   Web Audio API (CC-103), so they are our own code.
4. **Fonts.** None are files. ADR-012 uses system font stacks only, no `@font-face`.
5. **Gaps.** No credits file, nothing that fails when an asset is added without a licence, no rules for an
   artist, no size limit, and no Bit drawing yet (CC-153 and CC-194 assume one, ADR-024 says a person draws it).

### 2. How others do it

1. **Wikimedia Commons** (commons.wikimedia.org/wiki/Commons:File_description_page, read 2026-10-18). Every file
   has a description page with the `{{Information}}` template: description, date, source, author and permission,
   plus a machine readable licence tag. The Cburnett king, `File:Chess_klt45.svg`, records author Cburnett, date
   27 December 2006, source "Own work", and four licences "of your choice": GFDL 1.2+, CC BY-SA 3.0, BSD (3 clause)
   and GPL 2+. The lesson: one record per file with the same five facts, kept next to the file.
2. **REUSE** (FSFE, REUSE Specification 3.3, 2024-11-14, reuse.software/spec-3.3/). Every file carries
   `SPDX-FileCopyrightText` and `SPDX-License-Identifier`. Files that cannot hold a comment (images, sounds) get a
   `name.ext.license` file beside them or an entry in one `REUSE.toml` at the root (the older `.reuse/dep5` is
   deprecated). Licence texts live in `LICENSES/`. Our own unpublished licence would be a `LicenseRef-*` id. The
   `reuse lint` tool fails a build when a file has no licence.
3. **SPDX** (spdx.org/licenses, read 2026-10-18). Short ids for every common licence, including art licences:
   `CC0-1.0`, `CC-BY-4.0`, `CC-BY-SA-3.0`, `MIT`, `BSD-3-Clause`, `OFL-1.1` for fonts. Custom terms are
   `LicenseRef-<name>`. Using these ids makes a record machine checkable and unambiguous.
4. **Game jams and small game projects.** Ludum Dare and itch.io jams ask entrants to list third party assets with
   author, licence and link, usually in a `CREDITS.md` or `credits.txt` and on the credits screen. OpenGameArt
   (opengameart.org) shows the licence on every asset page and asks for "Attribution instructions". Kenney's assets
   (kenney.nl) are CC0 and need no credit, but most teams credit them anyway. Godot keeps `COPYRIGHT.txt` in the
   Debian machine readable format, one stanza per path pattern.
5. **Creative Commons attribution** (wiki.creativecommons.org/wiki/Best_practices_for_attribution). A CC BY credit
   needs TASL: title, author, source link and licence link, and a note if the work was changed.

### 3. Licence compatibility for us

ClassiCade is closed source and will earn money from cosmetics and a subscription (BRD, Stage 3). Our own art,
and above all Bit, is the brand. So:

1. **CC0 1.0** (public domain dedication). Use freely, no notice needed. We still credit it.
2. **CC BY 4.0.** Commercial use and changes allowed. We must credit the author (TASL) and say if we changed the
   work. Fine, CREDITS.md and a credits page do that.
3. **MIT, BSD-3-Clause.** Software licences, but fine for art: keep the copyright notice and licence text with the
   copies. Fine.
4. **OFL 1.1** for any font we ever add: free to embed, the font cannot be sold on its own. Fine.
5. **Not CC BY-SA (ShareAlike).** Any adaptation (a recolour, an animation, a derived skin) must be shared under
   BY-SA too. Our neon recolours and cosmetics would then be free for anyone to copy and sell, and where an
   adaptation ends is unclear (a board drawn around a piece? Bit holding one?). It also cannot mix with art we keep
   all rights to.
6. **Not NC (NonCommercial).** We plan revenue, and "not primarily intended for commercial advantage" is unclear
   even for a free site with a paid tier. One store item later would put every NC asset in doubt.
7. **Not ND (NoDerivatives).** We recolour everything to the neon tokens, which is a derivative.
8. **The chess pieces.** Our pieces record says CC BY-SA 3.0, but Commons offers the Cburnett set under four
   licences of our choice. We choose **BSD-3-Clause**, which is permissive: keep the notice "Copyright © Colin
   M.L. Burnett", the conditions and the disclaimer with the files. `public/pieces/LICENSE.md` now carries that
   text, and CREDITS.md records the choice. Our own piece set (a cosmetic, CC-153 or the store) can replace them
   later.

### 4. Commissioned art in India (general guidance, not legal advice: for a lawyer)

Under the Copyright Act 1957:

1. **The artist owns it first.** Section 17 makes the author the first owner. The employer owns work made under a
   contract of service (an employee), but a freelancer works under a contract for services and keeps the
   copyright. Section 17(b) gives a painting or portrait made "for valuable consideration at the instance of" a
   person to that person, but whether a digital vector mascot is a "painting" is uncertain. Do not rely on it.
2. **Assignment must be written.** Section 19(1): an assignment is valid only in writing, signed by the artist. It
   should name the works, the rights, the territory, the term and the fee.
3. **Traps in section 19.** If the term is not stated it is 5 years (19(5)). If the territory is not stated it is
   India only (19(6)). If the buyer does not use the rights within a year, the assignment lapses unless the deed
   says otherwise (19(4)). So the deed must say: worldwide, for the full term of copyright, all media now known or
   later invented, and that 19(4) lapse does not apply.
4. **Moral rights stay with the artist** (section 57): the right to be named and to object to distortion that
   harms their reputation. They cannot be assigned, and a waiver may not hold. Credit the artist, and get their
   written consent to the changes we will make (recolour, resize, animate, pose, crop).
5. **Warranties.** The artist promises the work is original, not traced or copied, and not made with generative
   AI (copyright in AI output is unsettled in India and elsewhere, and ADR-024 wants Bit drawn by a person). The
   artist hands over the editable source (SVG) and, ideally, sketches as proof of process.
6. **Stamp duty** on an assignment deed depends on the state. A lawyer drafts the deed once and we reuse it.

**Flag for the owner:** have a lawyer draft one reusable "assignment of copyright for commissioned artwork" deed
before any artist is paid.

### 5. What is best for ClassiCade

1. **One human readable record, checked by a test.** `docs/CREDITS.md`: one table row per asset file with author,
   licence (SPDX id), source and date, the five Commons facts. A unit test fails when a file has no row, a row names
   a missing file, or a licence is not on our allowlist. That is the core of REUSE without adding a tool, a
   `LICENSES/` folder or a sidecar file per image, which would double our file count for 20 assets. If we ever
   publish the code, the same rows convert to a `REUSE.toml`.
2. **Art drawn in code is recorded too,** one row per component file under `apps/web/src/art`, so Bit and its
   replacements are covered by the same test.
3. **Allowed licences:** `LicenseRef-ClassiCade` (ours, all rights reserved), `CC0-1.0`, `CC-BY-4.0`, `MIT`,
   `BSD-3-Clause`, `OFL-1.1`. Never BY-SA, NC or ND.
4. **Our own art** is "ClassiCade, all rights reserved" (SPDX `LicenseRef-ClassiCade`). ADR-050 was not on
   `main` when this was written. If it says otherwise, CREDITS.md follows it.
5. **Commissioned art** comes with a signed assignment (section 4), and is then recorded as ours with the artist
   named in the author column.
6. **A placeholder Bit now** (owner's choice), drawn by hand in code from the STORY_MODE.md brief, credited as a
   placeholder. The artist's version replaces the drawing inside the same component, so callers do not change.

## Why

Every asset must be safe to use in a product that will charge money, and Bit is the brand. Without a record a
licence problem surfaces only when someone complains. CC-153, CC-194 and CC-259 need a Bit to place.
