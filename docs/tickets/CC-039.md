## Why

Three Tic-Tac-Toe opponents for three kinds of player: someone learning the game, someone who knows the basics,
and someone who wants to prove they can at least draw against perfect play.

## Scope

- In: `packages/games/src/bots/tictactoe/tictactoeBot.js` implementing the CC-038 `Bot` contract.
- Out: seating bots in rooms (see CC-038 "Planned wiring").

## Levels

| Level      | Plays                                                                                                         |
| ---------- | ------------------------------------------------------------------------------------------------------------- |
| Easy       | A random free cell. When it can win at once it notices only half of the time.                                 |
| Medium     | Wins if it can, else blocks, else the centre, else a random free corner, else any free cell. A fork beats it. |
| Unbeatable | Full minimax. Wins sooner score higher, so it finishes games. Equal best moves are picked at random.          |

Unbeatable remembers every solved position in a module level map. That is safe because a position's score never
changes and Tic-Tac-Toe has only 5,478 positions, and it makes a move cost microseconds after the first game.

## Acceptance criteria

- [x] Unbeatable never loses, proved by an exhaustive test over every line the opponent can play, as first and
      second player, following every tie-break the bot could make at each of its turns.
- [x] Medium takes wins, blocks, prefers centre and corners, and loses to the classic corner fork.
- [x] Easy sometimes misses an immediate win.
- [x] Contract kit (CC-038) passes for every level.
- [x] Tests cover every branch.

## Verification

Exhaustive proof (`tictactoeBot.test.js`): when it starts, 10,640 lines end in 7,056 wins and 3,584 draws. When
it replies, 6,112 lines end in 2,528 wins and 3,584 draws. No losses.
