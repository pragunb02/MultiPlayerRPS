## Scope

- In:
  - `/signup` and `/login`: labelled `Field` component (hints/errors wired with `aria-describedby`/`aria-invalid`),
    instant validation mirroring server rules, server field errors placed on the right field, generic login error,
    return to `?next=` — **only same-site paths**, so a crafted link cannot redirect off-site.
  - Signup tells guests their guest games don't move to the new account yet (CC-032) — honest UX.
  - Header: guests/visitors get Log in + Sign up (carrying the current page as `next`), users get Log out; Profile for
    anyone with an identity; stable header height.
  - `/profile`: level, accessible progress bar, XP totals, W/L/D, match history newest first with "Load more"; empty,
    anonymous and guest states.
- Out: avatars/public profiles (CC-034), password reset (CC-033), guest → account merge (CC-032), replays (CC-041).

## Verification

- 720 tests (5 consecutive green runs); 93 web tests incl. open-redirect protection, validation, server field errors,
  header states, paging.
- Real-browser journey (Playwright) against the real server + MongoDB: sign up → play Tic-Tac-Toe vs a guest →
  profile shows the win and XP → log out → wrong password (generic message) → log in again. No browser errors.
  Screenshots reviewed; fixed a 10 px header height jump on sign-in.
