## Problem

In a rematch the same player can move first game after game. Root cause: `accepting` in
`apps/server/src/domain/rooms/roomComponent.js` reverses the seats and draws a new seed, and its comment says that
makes the first move alternate. But the Tic Tac Toe and chess engines pick the starter with
`players[randomIndex(rng, players.length)]`, so reversing the seats only changes which seat the random draw lands
on. With any seed, each rematch is a coin toss, not a swap (BUG-23).

## Fix

The Tic Tac Toe and chess engines take an optional `starter` in `init` (in chess the starter plays White) and say
who started with a new optional engine hook, `starterOf(state)`. Game 1 of a room still draws the starter from the
seed. Each accepted rematch gives the first move to the player after the one who started the previous game, read
from that game's stored state, so it also holds after a server restart. The room records the starter in
`room.game.starter` and the match record keeps it beside the seed, and `replayGame` passes it back to `init`, so a
replay is exact. With no `starter` the engines behave exactly as before. RPS has no hook and is unchanged.

**Research note.**

1. Our code today: see the root cause. The seat reversal came with the first rematch (CC-037, ADR-015) and was
   meant to swap X and White, but the engines never read the seat order for that.
2. Lichess swaps colours in a rematch: `Rematcher.scala` builds the new game with `!color` when
   `rematchAlternatesColor` is true, its normal case
   (https://github.com/lichess-org/lila/blob/master/modules/round/src/main/Rematcher.scala). Chess.com rematches
   also swap colours. For Tic Tac Toe, taking turns to go first is the usual fair rule, since X has the advantage.
3. Best for ClassiCade: alternate on every accepted rematch, as the product vision says (PRODUCT_VISION.md, "the
   starter alternates (CC-091)"). Keep the seed for game 1 so the first game stays a fair draw.

**What else uses the same path.**

1. Games against computer characters: the computer accepts a rematch through the room's normal answer
   (`botComponent.acceptRematch`), so the rematch goes through `accepting` and alternates too. Tested.
2. Pass and play does not use this path. `apps/web/src/games/passAndPlay/localMatch.js` `playAgain` calls
   `engine.init` again with the browser's random numbers, so the starter is still drawn each game. Not changed
   here: it is a browser change and needs its own ticket if wanted.
3. Chess ratings, puzzles and story mode create no engine state through `init` (puzzles use chess.js positions,
   ratings read finished matches, story mode is a document only). Bots never call `init`. Their behaviour is
   unchanged because the engines only change when `starter` is given.

**Edge case.** A rematch after an aborted game (nobody made a first move) still alternates from the aborted
game's starter, as the rule says: the starter of the previous game, whether or not it was played.

## Acceptance criteria

- **AC-1** Given a Tic Tac Toe or chess room, when three games are played through two accepted rematches, then the
  first move alternates each game (X and White go to the player who did not start the game before), whatever the
  seed.
- **AC-2** Given a series in progress, when the server restarts between games, then the next rematch still
  alternates.
- **AC-3** Given a game started by a rematch, when its match is recorded and replayed, then the replay gives the
  same final state, from the recorded seed, starter and log.
- **AC-4** Given an engine created with no `starter`, then its state is the same as before this change, and an RPS
  rematch records no starter.

## Test

`apps/server/src/domain/rooms/roomComponent.starter.test.js` plays series of three games in Tic Tac Toe and chess
with a seed that would give the same starter every game, restarts the room component over the same storage mid
series, plays a rematch against a computer character, and checks RPS. It failed before the fix (the second game
started with the same player). Engine tests cover `starter` and `starterOf`, `replay.test.js` the replay, and the
contract kit checks any engine that has the hook.
