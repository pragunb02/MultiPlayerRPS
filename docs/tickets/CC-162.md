## Why

After a game the biggest button was "Play again", which opened the lobby. It was not a rematch, and the opponent
who had asked for one waited up to 30 minutes, because the player still showed as connected (A1). The headline said
only "You won!" or "You lost", and the reason (a forfeit, the clock, a resignation) was below the fold or missing
(A11).

## Scope

- In: the result panel sits at the top of the room, above the board, with Rematch (or Accept, or Cancel) as its main
  action right under the headline.
- In: "Play again" becomes a secondary "New opponent". It leaves the seat in that room, which takes back any rematch
  request, and opens the game's lobby. The history entry is replaced, so Back never seats the player again.
  Spectators get "Play <game>" instead.
- In: the player still there is told at once: the room update, the rematch panel ("Bob left, so there is no rematch
  this time.") and a toast with the chime ("Bob left the room").
- In: the headline names the reason: "You won by checkmate", "You lost on time", "Draw by agreement", "You won by
  forfeit", "You won with three in a row", "You lost the best of 3". Each game words its reasons through the client
  game registry (`reasonPhrase`). An unknown reason keeps the plain headline.
- In, server: leaving a finished room keeps the leaver's display name in `rematch.leftName`, because their seat is
  gone, and the RoomView sends it. Nothing else changes: leaving a finished room already removed the seat, ended the
  rematch and broadcast the room.
- Out: the result card over the board and the bottom sheet on phones (CC-157, CC-172), the series history (CC-161).

## Acceptance criteria

- [x] Rematch is the main action in the result panel, near its top.
- [x] New opponent leaves the seat, withdraws the request, tells the other player and opens the lobby.
- [x] The headline names how the game ended, for every game, from the viewer's point of view.
- [x] Server: unit tests in `roomComponent.rematch.test.js`, integration test on MongoDB in
      `server.integration.test.js` (the name survives a read back from MongoDB).
- [x] Browser: `e2e/rematch.spec.js` (New opponent after asking), `e2e/chess.spec.js` (reasons), navigation updated.
- [ ] Docs updated (BACKLOG status, KNOWN_ISSUES, PROGRESS): left to the docs pass, this branch does not edit them.

## Plan / notes

- `leftName` is optional in the stored room and in the view, so rooms stored before this change read as before and
  older clients ignore it.
- The persistence layer is untouched: the room DAO stores `rematch` as it is given.
