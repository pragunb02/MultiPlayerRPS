## Why

Production still runs the legacy app with all its audit findings. The new stack has replaced every feature; it has to
go live, and the legacy code has to go so the findings can close.

## Scope

- In, part 1 — **cutover** (this branch):
  - Root `npm start` runs the new server.
  - `GET /health` on the new server, outside `/api` (no session, no CSRF guard): 200 `{status:"ok",database:"up"}` or
    503 — the same contract as the legacy app, so Render's health check path stays the same.
  - Production config requires `WEB_DIST_DIR` (a production server without the web build would answer every page
    with a 404 and still pass the health check). Relative paths resolve against the working directory — found in the
    rehearsal: `res.sendFile` refused the relative path, so every page answered 500.
  - DEPLOYMENT.md: new Render settings, variables and a cutover runbook (settings first, code second).
- In, part 2 — **delete legacy** (separate PR, after part 1 is verified live): `index.js`, `client/`, `models/`, `db.js`,
  `config.js`, `hw.txt`, legacy dependencies and scripts; the `MONGO_URI_PRODUCTION` fallback (CC-074); close the
  audit findings.
- Out: removing the legacy `users` collection (legacy players still migrate from it at login, CC-078).

## Acceptance criteria

- [ ] Render settings changed; new server live; `/health` up; game and legacy login verified in production
- [ ] Legacy code deleted; audit findings closed
- [x] Tests cover the change
