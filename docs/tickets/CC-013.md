## Why

In the legacy app a player is whatever name they type (SEC-01) and sockets are anonymous (SEC-03), so anyone can
play as — and inflate the stats of — anyone else. Every later feature (rooms, matches, ratings) needs a trustworthy
answer to "who sent this?".

## Scope

- In:
  - MongoDB connection per app instance (Mongoose 9, no global state); sessions in MongoDB (`connect-mongo` 6,
    collection `player_sessions`, TTL index; separate from the legacy `sessions` collection).
  - `models/identity` (guest | user, validated, frozen); `domain/identity` creates guests (injected generators).
  - Session middleware (`cc.sid`: HttpOnly, SameSite=Lax, Secure in production, 7 days); `saveUninitialized: false`;
    identity re-validated on every read; session id regenerated when an identity is stored (no fixation).
  - `GET /api/session`, `POST /api/session/guest` (rate-limited), `DELETE /api/session`.
  - Realtime gateway (Socket.IO 4.8): origin allow-list, same session middleware, connections without a valid
    identity refused with `UNAUTHORIZED`; identity read from the session only; standard acknowledgements
    `{ ok, data } | { ok, error }` with the same error translation as HTTP; logout disconnects that session's sockets
    (domain-event style: HTTP publishes "session ended", the gateway subscribes).
  - Config: `MONGO_URI`, `SESSION_SECRET` (≥ 32 chars), `ALLOWED_ORIGINS` (required in production).
- Out: user accounts / login (CC-076), guest → account upgrade (CC-032), CSRF tokens (CC-030), socket rate limits (CC-015).

## Acceptance criteria

- [x] No HTTP or socket path accepts identity from client input (tests try to spoof it)
- [x] Sockets without a session, with a forged cookie, or from a foreign origin are refused
- [x] Sessions persist in MongoDB and survive a server restart
- [x] Logging out disconnects only that session's sockets
- [x] Config fails fast on missing/weak values
- [x] Tests, lint, format, coverage, audit pass; ran for real

## Notes

- Bug found and fixed during testing: `connect-mongo` creates its TTL index in the background; shutting down right
  after boot produced unhandled rejections (fatal in production). The store is now awaited until ready at startup.
- The legacy app (what production runs) is unchanged; SEC-01/SEC-03 are fixed in the new stack and close fully when
  the games move over and legacy is deleted (CC-029).

## Verification

- 165 tests (unit with in-memory session store + integration with real in-memory MongoDB), 5 consecutive green runs;
  98.9 % lines. Lint 0, audit 0.
- Live run against MongoDB: guest created → session read back → socket identity matches → foreign origin rejected even
  with a valid cookie → logout 204 + socket disconnected → graceful shutdown closes the database.
