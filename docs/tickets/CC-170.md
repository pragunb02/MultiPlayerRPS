## Why

"Every click gives a visible response within 100 ms" is only true if a test keeps it true for every control in
every state, including the ones nobody thinks to click.

## Scope

- In: `e2e/controlProbe.js`, the audit's technique in a script installed before the page's own: a MutationObserver
  over the document, socket sends and fetches, Web Audio oscillators other than the 1200 Hz click sound, and the
  address. Elements marked `data-cc-ticker` (chess clocks, the rematch countdown) change by themselves and never
  count, nor does a moved `tabindex`.
- In: `e2e/matchStates.js` brings two new players into each state of every game: waiting, my turn, their turn, a
  draw offer asked and asked of me (chess), finished as a win, a loss and a draw (Tic-Tac-Toe and chess), a rematch
  asked, asked of me and declined.
- In: `e2e/match-shell.spec.js` presses every distinct control in `main` (one of each name, one blocked and one
  ready where both exist) and fails if the presser sees no answer within 100 ms, or if a press that concerns the
  other player shows them nothing within one second. A press that ended the state is followed by a fresh pair in
  the same state. The header and footer are pressed on the home page. A PGN download counts as an answer.
- In: per state, the main controls must be wholly on screen without scrolling at 1280×720 (desktop project) and
  390×844 (mobile project). The four chess states CC-172 still has to fix are marked as expected to fail, with the
  reason, so the suite is green and a fix shows up as "expected to fail, but passed".
- Out: spectators, the promotion picker (not reachable without a long game) and Share (it opens the system sheet).
  The two browser flows for every request (ask, cancel, decline, accept, expire) stay in `e2e/requests.spec.js` and
  `e2e/rematch.spec.js`, and grow with the generic requests of CC-159 and CC-160.

## Acceptance criteria

- [x] Every control in every listed state answers within 100 ms on desktop and mobile.
- [x] Presses that concern the other player reach them within one second.
- [x] The fold check runs for every state and viewport. Known layout gaps are expected failures with a message.
- [x] Runs green twice in a row with `E2E_PORT=4966 npm run test:e2e`.
