## Why

Production runs on a free Atlas cluster with no backups of our own. A bad migration, a bug that deletes documents,
a leaked admin credential or the free cluster going away would lose every account, level and match. We need a copy
we control, that only the owner can read, and a restore we have actually tried.

## Scope

- In:
  - `.github/workflows/backup.yml`: nightly (03:17 UTC) and manual. `mongodump --gzip --archive` streamed into
    `age` with the owner's public key(s), uploaded with the AWS CLI to an S3 compatible bucket (R2, B2 or S3) whose
    lifecycle rule keeps 30 days.
  - Skips with a notice while no secret is set. Fails, naming the secret, when only some are set or one is malformed
    (a private key pasted as the public key is caught and called out).
  - Before every dump, proves the database user can only read (MongoDB `connectionStatus` with privileges, compared
    with the read roles' actions) and that the database has collections (a wrong database name would otherwise give
    an empty backup that looks fine).
  - Never an Actions artifact or cache, `--quiet` dump, database password masked in all later log lines, secrets
    only in the steps that need them, dependencies installed with `--ignore-scripts` before any secret is present.
  - `scripts/bin/backup.mjs restore` and `summary` for the owner: decrypt and restore in one pipe into an empty
    `restore_*` database only, then print counts. `docs/runbooks/backup-restore.md`: setup, restore, verification,
    disaster restore, rehearsal checklist, failure table.
  - `.github/actions/backup-tools`: MongoDB Database Tools pinned with MongoDB's SHA 256, `age` from Ubuntu.
  - CI job "Backup round trip": the real pipeline on every PR against an access controlled in memory MongoDB.
  - CI job "Workflow files": actionlint (with shellcheck) on every workflow, shellcheck on the dump script.
- Out: point in time recovery, backing up anything besides the database, automatic restore drills, alerting beyond
  GitHub's failed run emails.

## ADR-0xx (proposed) — Backups: age encrypted mongodump to an S3 compatible bucket, from GitHub Actions

**Context.** The repository and its Actions logs and artifacts are public. The database is a free Atlas cluster
(no Atlas backups on the free tier). We have no servers of our own and want no paid services.

**Decision.**

1. **Run in GitHub Actions** on a schedule. Free, already trusted with the code, and the secrets stay in GitHub.
2. **`mongodump --gzip --archive` piped into `age`.** One file per night, never unencrypted on disk. Restores with
   the standard `mongorestore`.
3. **age, not gpg.** One small public key string as the secret, no keyring or trust model, modern defaults
   (X25519, ChaCha20 Poly1305), and several recipients for a spare key. Only the owner's private key decrypts.
4. **Any S3 compatible bucket**, chosen by the owner through secrets (endpoint, bucket, key, optional region). R2 is
   the suggested default (10 GB free, no egress fees), B2 and S3 work the same way.
5. **Retention by the bucket's lifecycle rule, not by the workflow.** The workflow's key needs no delete right, so a
   leaked key can add junk but not wipe history (on R2, a bucket lock makes that hard guarantee).
6. **Read only is checked, not trusted.** Each run inspects the user's actual privileges and refuses to dump with a
   user that can write.

**Alternatives.** Atlas cloud backups (needs a paid tier). Committing encrypted dumps to a private repository (git
is a poor store for large binaries and another credential). Actions artifacts (public on this repository, so never).
A cron job on Render (free instances sleep and have no persistent disk). gpg (heavier setup for the same result).

**Consequences.** The owner must keep the private key safe in two places, or every backup is unreadable. If nightly
runs stop for 30 days the lifecycle rule leaves no backup, so failed run emails must be acted on. The Atlas access
list must allow GitHub's runners (in practice `0.0.0.0/0`, guarded by the password). Upgrading the Database Tools
means updating the pinned URL and checksum; the round trip CI job proves the new version.

## Plan / notes

- Logic lives in small tested modules under `scripts/backup/` and `scripts/lib/`. `scripts/bin/*.mjs` only wire the
  real driver, processes and clock (excluded from coverage like `apps/server/src/index.js`).
- The dump step is `scripts/backup/dump-and-encrypt.sh`, used by the workflow and by the round trip test, so the
  test runs exactly what production runs.
- MongoDB 8 grants `performRawDataOperations` and `planCacheRead` with the read roles. Both are on the allowlist,
  found by testing against a real `mongod` with access control.
- `mongodb` (already in the tree through mongoose, same version) is now also a root dev dependency, because the
  scripts at the root use it directly. No runtime change.

## Verification

- Unit tests for every module and branch: config checks, privilege check, archive check, object key, argument
  parsing, pipes between real processes, restore guards, the command line and its error output.
- Against an in memory MongoDB with access control on: a `readAnyDatabase` user passes, `readWrite` and admin users
  are refused, a database without collections is refused, restore guards refuse non scratch and non empty targets.
- Round trip with mongodump 100.19.1 and age 1.3.2 (locally) / 1.1.1 (Ubuntu 24.04 in CI): dump with the read only
  user through the real script, file is age encrypted with no plaintext, restore into `restore_roundtrip`, every
  document (ObjectId, Date, Decimal128, nested) and index identical, only the named database is in the backup, a
  second restore into the same database is refused, a different key can not decrypt.
- `config` run with no secrets prints the "Backup skipped" notice and exits 0.
- actionlint 1.7.12 and shellcheck clean.
