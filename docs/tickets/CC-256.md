## Research (written before any code)

### 1. How our code does it today

1. Sign-up allows 3 to 20 letters, digits and underscores (`apps/server/src/models/credentials.js`,
   `SignupPage.jsx`). A name has no space or hyphen, so the browser finds no place to break it: it is one word.
2. Names are drawn in many places: the header (`Layout.jsx`, `.name`), home's "You're playing as …"
   (`HomePage.jsx`, `.ready`), the profile's `<h1>`, the room's seats (wraps since CC-275), the turn and status lines
   of the boards (`RpsBoard.jsx`, `FairnessLock.jsx`, `TurnBanner.jsx`, `ClaimWin.jsx`, `ComputerNote.jsx`), the
   rematch panel and the leaderboard rows (`LeaderboardPage.module.css` `.name` already cuts off with an ellipsis).
3. Only the seat name (CC-275) has `overflow-wrap: anywhere`. Nothing else may break a name.
4. The page is a CSS grid (`Layout.module.css` `.shell`, rows only, so one `auto` column). Grid and flex items have
   `min-width: auto`, so the narrowest the column can be is its widest unbreakable word. One long name in `main`
   makes the whole column, header included, wider than the phone.
5. The browser tests sign up with 15 character names on purpose, because 20 broke the phone layout
   (`e2e/personas.js`, CC-237). So no test sees a 20 character name.

Measured on 2026-10-19 on main `b173cd4`, Pixel 7 emulation, a 20 character name of wide letters (`W`×10 and 10
digits, the widest a name can be), with a probe that lists every element past the right edge:

| Screen                           | 360 px wide | 412 px wide | What is too wide                                  |
| -------------------------------- | ----------- | ----------- | ------------------------------------------------- |
| Home                             | 376 px      | 412 px      | "You're playing as …" pill (`.ready`)             |
| Profile                          | 612 px      | 612 px      | the `<h1>` with the name, 580 px, then everything |
| Lobby, room, result, leaderboard | 360 px      | 412 px      | fine                                              |

When the profile is 612 px, the header is 612 px too, so its Menu button (and in the menu, Log out) is off the
screen, and the phone zooms out. That is what CI run 39072590323 saw in CC-237: the name covering Log out, and the
change password form lying over "Sign out other devices".

### 2. How others do it

Sources read on 2026-10-19.

1. **MDN, `overflow-wrap`** (last modified 2026-07-21): with `anywhere`, "soft wrap opportunities introduced by the
   word break are considered when calculating min-content intrinsic sizes". With `break-word` they "are NOT
   considered". So `break-word` breaks a long word in a plain block but does not stop a flex or grid item from
   growing. Only `anywhere` (or `min-width: 0` on the item) does.
2. **Ahmad Shadeed, Defensive CSS, "Minimum content size in CSS flexbox"** (defensivecss.dev, © 2024): "If a flex
   item has a text element or an image that is bigger than the item itself, the browser won't shrink them." The fix
   is `min-width: 0` on the item, with wrapping or an ellipsis on the text.
3. **MDN, `contain`** (last modified 2026-09-07) and **MDN, `clamp()`** (last modified 2026-08-12): containment
   clips a box's descendants to it, and `clamp()` sizes text between a minimum and a maximum. Neither is needed
   here: a name must be read in full, not clipped, and our heading sizes already step down on phones.
4. **MDN, viewport meta** (last modified 2026-09-23): content wider than the viewport makes the browser zoom out,
   and MDN says "you should usually avoid overflowing content horizontally".
5. Products (from using them, general knowledge, high confidence): GitHub, Discord and Chess.com cut a long name with
   an ellipsis in compact rows (a header chip, a list row) and show the whole name where it is the subject (the
   profile heading), wrapping it there.

### 3. What is best for ClassiCade

1. Fix the cause where the page is built: let every name break when it does not fit. `overflow-wrap: anywhere` on
   the page's content (`main`) and on the header's name. It is inherited, and it only breaks a word that cannot fit
   on its line, so ordinary text looks the same. The `nowrap` navigation strip keeps its own rule.
2. Give the shell's one column `minmax(0, 1fr)`, so a too-wide child can no longer widen the header and push the
   Menu button off the screen. It does not hide anything: overflow still counts in the page width, and the check
   still sees it.
3. Keep the full name everywhere it is shown today (a name is how friends find each other), wrapping instead of an
   ellipsis. The leaderboard keeps its ellipsis, because a row of places must stay one line.
4. No `overflow-x: hidden` or `clip` on the page: it would cut content off and hide the bug from the check.
5. Test with a 20 character name of wide letters on every main screen, at 360, 390 and 412 px, for the player and for
   the opponent who sees the name (`e2e/layout-width.spec.js`, with CC-270). `e2e/personas.js` gets a
   `longNameAccount` beside `newAccount`, with a unit test that sign-up accepts it and that it is 20 characters.

## Root cause

A username is one unbreakable word up to 20 characters, and grid and flex items never get narrower than their
longest word (`min-width: auto`). The profile heading and home's greeting had no rule to break it, so on a phone
they made `main`, and with it the one-column shell and the header, wider than the screen.

The new check (`e2e/layout-width.spec.js`) found two more causes the probe had not reached:

1. The opponent's score line under the board, "Best of 1 · You 0 – WWWWWWWWWW…", made the guest's result 401 px wide
   at 390 px. Same cause as the profile heading, fixed by the same rule.
2. On Firefox the lobby was 391 px wide at 360 and 390 px, with no name in it: Firefox sizes the room code field
   (20 characters of a monospaced, letter-spaced font) wider than the card, and as a grid item it could not shrink.

## Fix

1. `Layout.module.css`: the shell's one column is `minmax(0, 1fr)`; `main` has `overflow-wrap: anywhere`, so a word
   too long for its line breaks, and every name in the page with it; the header's name has `min-width: 0` and
   `overflow-wrap: anywhere`.
2. `PlayPage.module.css`: the lobby's fields have `min-width: 0`.
3. No `overflow-x: hidden` or `clip` anywhere. No test was loosened.

## Verification

1. `e2e/layout-width.spec.js` (new, part 2 of the CI browser suite): at 360×800, 390×844 and 412×915, with a 20
   character name of ten Ws, home with the menu open, the lobby, the room waiting, the room playing (both players),
   the result after a win and after the level-up (both players, every frame), the leaderboard and the profile with the
   menu open: `scrollWidth <= innerWidth`, the window never widened past the phone, and the Menu button, the name
   and Log out inside the screen.
2. Before the fix (main's CSS) it failed on all three sizes on Chromium mobile: home 373 px at 360, the guest's
   result 401 px at 390, the profile 612 px at 412. On Firefox the lobby, 391 px. After: 3 of 3 pass on Chromium
   desktop, Chromium mobile, Firefox and WebKit.
3. `e2e/personas.test.js`: `longNameAccount` is 20 characters and sign-up accepts it (2000 tries), and its exact
   shape.
4. Also run on Chromium desktop and mobile: `screens.spec.js`, `visual.spec.js`, `dead-space.spec.js`,
   `names.spec.js`, `match-shell.spec.js`, `leaderboard.spec.js`, `user.spec.js`. All pass. Two tests failed once
   each while seven files ran in parallel and passed alone three times out of three: `match-shell.spec.js:138`
   tictactoe "computer lobby" on desktop (two lobby controls below the fold) and `user.spec.js:119` (the password
   changed status took over 5 s). Neither touches what this PR changed.
5. `npm run lint`, `npm run format:check`, and the unit tests of `e2e/`, `scripts/`, `Layout`, `PlayPage` and
   `ProfilePage`.
