## Why

Opening a friend's invite link in a browser without a session silently created a guest and seated it. The owner
asked for a choice instead: "I copied the invite link — do I log in, or play as a guest?" A player with an account
ended up seated as a stranger, and their game never counted for them.

## Scope

- In:
  - `/games/:slug/rooms/:code` (and the old `/room/:code`) for a visitor **without a session** shows a chooser
    (`pages/RoomPage/JoinChooser.jsx`): "You're invited to play {game}", the room code, and three ways in —
    **Play as guest** (starts the guest session, then joins at once), **Log in** and **Sign up** (both
    `?next=<this room>`, so the player comes straight back, joined as the account).
  - Focus moves to the heading when the chooser appears; a failed guest start is announced (`role="alert"`) and
    the button works again.
  - While the session is loading the page says "Joining room …" — no chooser flash, no join. A session that can't
    be loaded shows "Can't join this room" with the reason.
  - Someone with a session (guest or account) skips the chooser: the existing join flow.
  - `useRoom(code, { enabled })` no longer starts a guest session; the page enables it once there is a session.
- Out:
  - The chooser's illustration (`art/illustrations/InviteArt.jsx`) belongs to CC-087; the chooser is a plain card
    until that lands, with a slot that needs no logic change.
  - "Play as a guest" on the home page and creating a room from a lobby stay one click, as before.

## Acceptance criteria

- [x] No `POST /api/session/guest` until "Play as guest" is clicked (browser test counts the requests).
- [x] Log in / sign up from the chooser lands in the room as the account; Back never shows the form again; Back from
      the login page shows the chooser again.
- [x] Back, Forward and reload on the chooser keep it; a person who already has a session goes straight in.
- [x] Old `/room/:code` links: the chooser names no game; after joining, the URL becomes the canonical one.
- [x] Tests cover the change (unit, browser).
- [x] `npm run lint`, `npm run format:check`, `npm run test:coverage`, `npm run test:e2e` pass.
- [ ] Docs updated (BACKLOG status, KNOWN_ISSUES, PROGRESS) — by the coordinator when merging.

## Plan / notes

- The gate covers every arrival at a room URL without a session, including "Join room" by code from a lobby: it is
  the same URL, and a visitor typing a code has not chosen how to play yet either. Browser tests that opened room
  links in fresh browsers now choose "Play as guest" first (`joinAsGuest` in `e2e/fixtures.js`).
- CC-085 gets stronger for free: after logging out in a room, Back shows the chooser — nobody is seated.
- Choosing happens before any server call, so a link to a room that doesn't exist shows the chooser first and "Room
  not found" after the choice (the server only answers room questions for a session).

## Found along the way

- **Every page answered 500 when the checkout lives below a dot-folder** (e.g. `~/.worktrees/…`): `res.sendFile`
  with an absolute path refuses any path containing a dot-segment. `index.html` is now sent relative to the build
  folder (`{ root: distDir }`), with a regression test in `webSecurity.test.js`. Needs a ticket number from the
  coordinator (bug, P2); production on Render is not affected (its path has no dot-folder).
