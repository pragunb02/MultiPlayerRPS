## Prerequisites

1. CC-123: the brand domain, so email can be signed with SPF and DKIM.
2. CC-293: the transactional email service.
3. Before 13 May 2027, email to an under 18 player needs the parental consent step (ADR-028.9).

## Research (written before any code)

The builder writes this section before any code (working agreement rule 4): how sign-up, sessions and the guest
transfer work today, how other products do magic links (with sources), and what is best for ClassiCade. The design
below is what the owner agreed on 2026-10-20.

## Why

A guest's progress lives only in one browser's cookie. Signing up needs a username and a password, which many
guests skip. One email address is a smaller ask, and it makes the progress safe on any device.

## Design (agreed with the owner, 2026-10-20)

### Saving

1. The guest gives an email address and a birth year from the neutral picker (ADR-048.7). Under 13 is refused
   (ADR-048.8).
2. The answer is always "Check your email", whether or not the address is already in use, so nobody can find out
   who plays here (CC-118).

### The link

1. The token is 32 random bytes. Only its SHA-256 hash is stored, in `email_links`
   `{hash, guestId, email, purpose, expiresAt, usedAt}`. A link is valid for 30 minutes and works once. A TTL index
   removes old links.
2. The link is `/save#token`. The token stays in the URL fragment, so it never reaches server logs or a `Referer`
   header, and the page sends it in a POST.
3. The server checks it with one atomic update: the link must be unused and unexpired, and the same update marks it
   used.

### What happens next

1. **A new email** creates an account with the email confirmed, and the guest's data moves to it through the
   ADR-014 transfer.
2. **An email that already has an account** signs that account in and merges the guest's data into it.
3. In both cases the session id is rotated. The old device sees "saved on another device".
4. Later sign-ins use "Email me a link", or an optional password.

### Reminder

With the player's opt-in, one reminder email when a saved guest has not visited for 25 days (the session ends at
30, ADR-030), with an unsubscribe link.

### Limits

Rate limits per session, per network address and per email address.

### Entry points

CC-097's "Save your progress" prompts (first win, level-up, streak at risk, session ending soon) lead here.

The owner's idea to "extend guest mode by 10 or 30 days, 2 or 3 times" is not needed: guest sessions already roll
30 days from the last visit (ADR-030.1, ADR-030.3).

## Scope

- In: the save form, `email_links`, the `/save` page, the new account and merge paths, session rotation, "Email me
  a link" sign-in, the optional password, the opt-in reminder, the rate limits.
- Out: the email service itself (CC-293), password reset (CC-033), the parental consent step.

## Acceptance criteria

- [ ] Research section written before any code
- [ ] The answer is the same for a new and an existing email (tested)
- [ ] Only the token's hash is stored; a used or expired link is refused; two requests with one link: only one wins
- [ ] The token never appears in a server log or a request URL
- [ ] The session id changes after saving, and the old device shows "saved on another device"
- [ ] Under 13 is refused in the page and by the server
- [ ] Tests cover the change
- [ ] `npm run lint`, `npm run format:check`, `npm test` pass
- [ ] Docs updated (BACKLOG status, KNOWN_ISSUES, PROGRESS, DATA.md and the privacy page for `email_links`)
