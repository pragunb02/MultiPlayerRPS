## Why

The legacy app has one hand-written set of room handlers per game, guessable codes, no cleanup, no disconnect
handling and duplicated events. One room system must run any engine, server-authoritatively.

## Scope

- In (by layer):
  - **shared** — socket event contracts (`room:create/join/leave`, `game:move`, `room:updated`, `room:closed`) with payload
    and `RoomView` typedefs; `ROOM_STATUS`; room-code alphabet (31 unambiguous characters, 6 long ≈ 887 million codes).
  - **models** — `parseRoomCode` (normalise + validate).
  - **persistence** — in-memory room DAO: deep copies in/out, optimistic versioning (Redis DAO later, CC-061).
  - **data** — room accessor: frozen domain rooms; NotFound/Conflict translation; no lost updates.
  - **domain** — room component: state machine waiting → playing → finished → closed; crypto room codes with collision
    retry; auto-start when full with a stored seed; moves via the engine (rejections → `ValidationError` with reason);
    forfeit on leave; host hand-over; disconnect/rejoin; expiry sweep (waiting 30 min, finished 10 min, abandoned 5 min);
    per-viewer views (engine `viewFor`, spectator view for non-members, never raw state or seed);
    domain events `room.closed`, `room.gameFinished`.
  - **service** — room socket handlers; strict payload validation (shape, unknown fields, size limits); per-socket token-bucket
    rate limit; personalised broadcasts; multi-tab-aware disconnects; `room.closed` → `room:closed` to clients;
    16 KB message cap.
  - **composition root** — engine registry from `ENGINES`, boot check that engines are in the catalog, domain event bus,
    sweeper every 60 s (cleared on shutdown).
- Out: real engines (CC-018–020), reconnect grace + timed forfeit (CC-036), rematch (CC-037), spectators (CC-057),
  match persistence/progression (CC-016/017, will consume `room.gameFinished`).

## Acceptance criteria

- [x] Any registered engine can be played end-to-end through sockets with no game-specific code in rooms or sockets
- [x] Identity only from the session; payloads cannot name another player
- [x] Unguessable codes; unknown/full/started rooms give clear errors
- [x] Disconnect/rejoin, leave/forfeit, host hand-over, expiry cleanup
- [x] Each viewer only receives their own view
- [x] Flooding is rate-limited
- [x] Tests, lint, format, coverage, audit pass; ran for real

## Verification

- 331 tests (5 consecutive green runs), incl. 15 end-to-end socket tests with two real guests playing a full game,
  forfeits, disconnect/rejoin, multi-tab, closure announcements and rate limiting. 98 % lines. Lint 0, audit 0.
- Live run: boots with an empty engine list; creating a room for an unregistered game, joining an unknown room and
  sending unknown payload fields are refused with the right error codes; clean shutdown.
