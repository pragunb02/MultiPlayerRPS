## Problem

The effects the product wants (celebrations, seasonal event themes, reward reveals, maybe a hero scene) had no
decided stack, no budgets and no single place to register them, so each would pick its own library or be hardcoded
in a component.

## Fix

A measured evaluation of 24 options (19 libraries and 5 platform features) and ADR-075, which sets the stack by
tier, the effect registry and the budgets, and amends ADR-016. Research note: our code today uses CSS on SVG for effects (`art/effects/`) and Motion
only on the chess board (ADR-016). Every candidate was built with `npm run build:web` on a throwaway branch, run
under the production server's own CSP in Chromium, Firefox and WebKit, and timed with CPU throttling; sources and
numbers are in [design/EFFECTS-STACK.md](../design/EFFECTS-STACK.md).

## Acceptance criteria

- **AC-1** Given the evaluation, when a builder adds an effect, then `docs/design/EFFECTS-STACK.md` names the tier,
  the library (or none), the registry entry it needs and the budget it must meet, and ADR-075 records the decision.
