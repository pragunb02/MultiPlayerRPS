## Problem

Some tests compared a fixed date with the real clock, so they passed only until a certain day (the challenge
fixtures of #152 would have failed from 2026-10-21 12:00 UTC, fixed in #164). Root cause: fixed fixture dates and
birth years in tests that do not own their clock.

## Fix

An opt-in future clock for the test runner (`CC_FUTURE_DAYS`, `scripts/testing/futureClock.mjs`,
`npm run test:future`), run nightly in India time, found every remaining one. Two server tests and one browser spec
used a fixed minor's birth year (2010, 2012) on the real clock: in 2029 and 2031 they would be adults. They now count
the year back from today (`apps/server/src/testing/birthYears.js`, `MINOR_YEAR` in `privacy.spec.js`). The flag
registry's "no flag past its removal date" check is an alarm on purpose and is tagged `clock-alarm`. The rule is in
ENGINEERING.md §4.16. The shuffled runs also found `flagPaths.test.js` checking "ran it both ways" before both runs
had happened in some orders; that check now runs after every test.

Research note: our own suite only. Searched for `2026-`, `Date.UTC(20`, epoch numbers, `expiresAt`, `removeBy`,
`FIRST_DAY` and fixed birth years, then ran every test 30, 365, 2200 and 7300 days ahead: the tests that own their
clock (`vi.setSystemTime`, an injected `now`) keep their fixed dates. A precise lint rule is not possible, because
whether a test owns its clock cannot be read from the text, so the nightly run is the guard. Sources: Vitest's
`--sequence.shuffle` and fake timers docs (vitest.dev, read 2026-10-21).

## Acceptance criteria

- **AC-1** Given the whole suite, when it runs 30 days ahead in UTC and 365 days ahead in India time, shuffled,
  then every test passes. Test: `npm run test:future` (nightly `future-clock` job) and the runs in the PR.
- **AC-2** Given the future clock, `Date.now()`, `new Date()` and `Date()` move ahead and dates built from a value do
  not. Test: `scripts/testing/futureClock.test.mjs`.
- **AC-3** Minor and adult birth years stay minor and adult on any day. Test: `apps/server/src/testing/birthYears.test.js`.

## Test

The two server tests failed 2200 and 7300 days ahead before the fix and pass after it, at 0, 400 and 7300 days.
