## Why

The 2026-10-17 audit ran axe on 140 screen states. It found one critical rule broken on every chess board in play,
a "needs review" on every Rock Paper Scissors screen, and, from reading the code, two gaps axe cannot see: the
chess board's keyboard model and what happens to focus when the page changes without a reload. Screen reader and
keyboard players are part of "anyone can play in one click" (PRODUCT_VISION.md), and nothing stops the same
mistakes coming back, because no test runs axe.

## Research

Done before any code, on 2026-10-18. Sources were fetched that day unless a date is given.

### How our code does it today

1. **Chess squares.** `games/chess/Board.jsx` draws a `role="grid"` named "Chess board", eight `role="row"` and 64
   `<button role="gridcell">`. Each square is named "e4, white pawn, legal move" and carries `aria-pressed` for the
   picked-up piece and `aria-disabled` when the board is closed. `aria-pressed` belongs to the button role. The
   explicit `gridcell` role replaces the button role, and `gridcell` does not support `aria-pressed`, so axe
   reports `aria-allowed-attr` (critical) on all 64 squares.
2. **Chess keyboard.** Since the audit's commit, CC-102 already gave the board a roving tabindex: only the square in
   `useBoardInput`'s `cursor` has `tabIndex=0`, the arrow keys move the cursor (flipped for Black), Enter and Space
   press the square button (pick up, then put down) and Escape drops the picked piece. Squares are
   `aria-disabled`, not `disabled`, so a player can explore while waiting. So the audit's "64 Tab stops" is gone on
   main. What is still missing from the grid pattern: Home and End (first and last square of the row), Ctrl+Home
   and Ctrl+End (first and last square of the board). Tests already rely on the names "e2, white pawn" and on the
   cell role (`e2e/chess.spec.js`, `e2e/matchStates.js`, `ChessBoard.test.jsx`, `RoomPage.alerts.test.jsx`).
3. **Page changes.** `components/Layout/Layout.jsx` has a "Skip to content" link to `#main`, and every page sets its
   `<title>` with `PageTitle`. Nothing happens to focus or to screen readers when React Router changes the page.
   After pressing a link that unmounts, focus falls back to `<body>` and a screen reader says nothing about the new
   page. The only programmatic focus is `JoinChooser.jsx` (its heading, on mount) and `Modal.jsx`.
4. **RPS score.** `games/rps/RpsBoard.jsx` puts `aria-label="Score"` on a `<p>`. A paragraph cannot be named, so
   the label is ignored by most screen readers and axe flags `aria-prohibited-attr`. `boards.test.jsx` finds the
   score by that label.
5. **No automatic check.** Neither the unit tests nor the browser tests run axe. The audit's scans were a one-off
   script in a scratch copy.

### How other products and references do it

1. **WAI-ARIA Authoring Practices, Grid pattern** (w3.org/WAI/ARIA/apg/patterns/grid, page dated 2026 by its
   copyright line). A grid is one Tab stop and the author moves focus inside it. Keys for a data grid: arrows move
   one cell and stop at the edges, Home and End go to the first and last cell of the row, Ctrl+Home and Ctrl+End to
   the first and last cell of the grid, Page Up and Page Down are optional. A cell may hold one widget that does not
   need the arrow keys (a button), and focus can sit on it. Selection is shown with `aria-selected` on the cell.
   Nothing in the pattern uses `aria-pressed` on a cell.
2. **WAI-ARIA 1.3 editor's draft** (w3c.github.io/aria). `gridcell` is a widget role that can be named by the author
   (so `aria-label` is right). `paragraph` is in the list of roles that cannot be named: authors must not use
   `aria-label` on it. ARIA in HTML allows `role="gridcell"` on a `<button>` (general knowledge, high confidence).
3. **Lichess** (github.com/lichess-org/lila, `ui/lib/src/nvui/render.ts` and `handler.ts` on master). The normal
   board (chessground) is not built for screen readers. Lichess has a separate "blind mode" that draws the board
   as a table (or plain divs) of `<button>`s with the square and piece as text, and no ARIA roles. Arrow keys move
   focus with `.focus()` (flipped for Black, a sound at the edge). Enter and Space are the native button click that
   picks and drops. Extra keys: a piece letter jumps to the next such piece, digits jump to a rank, `m` reads the
   legal moves, `l` the last move, `t` the clocks. Lichess does not set `tabindex`, so every square is a Tab stop,
   and it handles no Escape.
4. **Chess.com** (general knowledge, low confidence, not checked today). The board is a custom element of
   absolutely placed divs that is not exposed as a grid. Keyboard and screen reader play goes through typed moves
   and a separate accessibility mode, not through the board.
5. **Next.js route announcer** (github.com/vercel/next.js, `packages/next/src/client/route-announcer.tsx` on
   canary). After a client-side route change, a visually hidden `<p role="alert" aria-live="assertive">` reads
   `document.title`, else the first `<h1>`, else the path. It skips the first render and never moves focus.
6. **Gatsby user testing with screen reader users** (gatsbyjs.com blog, 2019-07-11, updated October 2019). Focus on
   the new page's heading tested best for screen reader users. Their recommendation was a skip link or the heading
   for focus, plus a live region that names the new page. Resetting focus to the top of the app was overwhelming,
   and a live region alone does nothing for sighted magnifier users.
7. **React Router** (general knowledge, high confidence). It does no focus management and leaves it to the app.

### What is best for ClassiCade

1. **Chess squares keep `<button role="gridcell">` and swap `aria-pressed` for `aria-selected`.** That is the grid
   pattern's own way to say "this cell is picked", it is allowed on `gridcell`, and every accessible name and role
   tests rely on stays the same. Wrapping each button in a `div role="gridcell"` would also be valid, but it changes
   the role every test queries and doubles the elements for no gain to the player. `aria-selected` is set on every
   square (true or false), as ARIA asks once any cell can be selected.
2. **Chess keyboard: complete the grid pattern on top of what CC-102 built.** Home and End go to the first and last
   square of the row as drawn (so `a` and `h` for White, the other way round for Black), Ctrl+Home and Ctrl+End to
   the top left and bottom right squares. Arrows, Enter, Space and Escape stay as they are. Lichess's extra letter
   and digit keys are an idea, not a fix, so they are left for `docs/IDEAS.md` under the feature freeze.
3. **Page changes: move focus to the new page's `<h1>` and say the new title politely.** This is what Gatsby's
   testing found best, plus Next.js's title announcement, but polite rather than assertive so it never cuts across
   a move announcement. Rules, so it never takes focus away from a player:
   1. Only a change of path counts. Room updates, rematches and the skip link's `#main` never change the path.
   2. The first page, and redirects that happen before the player has pressed anything (old or lower-case URLs
      replaced by the canonical one), do not move focus. That keeps CC-100's "no ring on page load" and keeps the
      skip link first in the Tab order on load.
   3. If the control that was pressed is still on screen inside `main` (a leaderboard tab), the page only
      announces. The player stays where they were.
   4. A page whose heading arrives later (a room that loads over the socket) is waited for. If the player has
      moved focus somewhere in the meantime, focus stays there. Only focus still on `<body>` or on the pressed
      header link is moved.
   5. A page with no heading after a while falls back to `main` as the skip target.
4. **RPS score: name it with words on the page, not a label on a paragraph.** A visually hidden "Score: " at the
   start of the paragraph reads "Score: You 1, Riya 0, Best of 3". No new role, no restyle.
5. **Axe in the browser tests.** Add `@axe-core/playwright` 4.14.0 (latest stable, depends only on `axe-core`
   ~4.14.0, peer `playwright-core`) as a dev dependency of the `e2e` workspace only. A new `e2e/accessibility.spec.js`
   visits every screen the suite reaches (pages, lobbies, join chooser, errors, every match state of every game
   from `matchStates.js`, the chess piece picked up, the resign and leave dialogs) in light and dark, on desktop and
   mobile, with the audit's tags (WCAG 2.0, 2.1 and 2.2 A and AA, best practice), and fails on any serious or critical
   violation. Nothing is allowlisted. Tic-Tac-Toe also uses `role="grid"` with nine Tab stops and no arrow keys. It
   is not in this ticket's scope and is named as a follow-up.

## Scope

- In: the four fixes above and the axe browser test.
- Out: Tic-Tac-Toe's grid keyboard model (follow-up), Lichess-style jump keys (an idea), colour contrast that axe
  cannot decide (the audit's own probe found no failures), restyling of anything.

## Acceptance criteria

- [x] No chess square carries `aria-pressed`. The picked square has `aria-selected="true"`.
- [x] Home, End, Ctrl+Home and Ctrl+End move the board's cursor, for both orientations.
- [x] A client-side page change moves focus to the new `<h1>` and announces the title, following the five rules.
- [x] The RPS score is not an `aria-label` on a paragraph and still reads "Score".
- [x] `e2e/accessibility.spec.js` fails on any serious or critical axe violation on every listed screen.
- [ ] Tests cover the change, coverage gates hold
- [ ] `npm run lint`, `npm run format:check`, `npm test` pass

## Plan / notes

See Research. BACKLOG, PROGRESS, DECISIONS and KNOWN_ISSUES are updated by the owner after merge.

What was built, file by file:

- `games/chess/Board.jsx`: `aria-pressed` became `aria-selected` on every square. The rank and file letters moved
  out of the square buttons into one `aria-hidden` layer drawn over the board, in the same places and colours.
  Found while building: a square showed "1a" as its visible text but was named "a1, white rook". WCAG 2.5.3 (label
  in name) asks the visible text to be part of the name, so a voice control user saying "click a1" was not helped by
  it. With the letters outside, a square has no visible text of its own and its name is the only label. axe runs
  that rule only as experimental, so the audit did not report it.
- `games/chess/chessGame.js`: `squareForKey` is the one pure function for the board's keys (arrows, Home, End, with
  Ctrl or Cmd for the corners). `isArrowKey` and `squareInDirection` are no longer exported.
- `games/chess/useBoardInput.js`: uses `squareForKey`, and only the board's own keys are kept from scrolling the page.
- `components/PageAnnouncer/PageAnnouncer.jsx`: the focus and announcement rules from the research, mounted once in
  `Layout.jsx` after `main`.
- `games/rps/RpsBoard.jsx`: a visually hidden "Score: " in the paragraph instead of `aria-label`.
- `e2e/accessibility.spec.js`: axe on every screen listed in the research, light and dark, both browser projects,
  plus two browser checks of page changes (focus on the heading and the title read out, focus left alone on the
  first page, Back counts, an opponent's move never takes focus off the board).
- `e2e/package.json`: `@axe-core/playwright` 4.14.0 as a dev dependency of the e2e workspace only. Render's build
  (`npm ci --include=dev`, DEPLOYMENT.md) installs it with the other dev dependencies, but the server never loads it.

Follow ups for the owner (not tickets, under the feature freeze): Tic-Tac-Toe's grid has nine Tab stops and no arrow
keys (a bug in something that exists, so it may get its own ticket). Lichess style jump keys (a piece letter, a rank
digit) are an idea for `docs/IDEAS.md`, which is on the working agreement branch and not on main yet.
