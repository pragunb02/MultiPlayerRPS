## Why

The UX audit found buttons that only looked disabled while they waited for the server, with no spinner and a toast
after eight seconds (A10), and board cells that did nothing at all when they could not be played (A12). A player
cannot tell a slow answer from a broken button.

## Scope

- In: `useAction(fn, { id })` and the phases on the app's `Button`: pressed (the CSS press and the click sound
  that was already there), waiting after 150 ms (spinner and "Sending…", the label kept underneath so the width
  stays, `aria-busy`), done (the change itself, or a check with a word such as "Copied" for 600 ms), disabled with
  a reason (`aria-disabled`, still focusable, the reason shown on hover, focus and press and announced), failed
  (the reason under the button, Retry only when trying again can help, see `isRetryable`).
- In: every control in the app converted and named with a stable `data-cc-control` id: header, footer, home,
  lobby, invite, join chooser, room, boards, rematch, requests, profile, auth, leaderboards, toasts and cards.
- In: board cells, hands and squares that cannot be played say why when pressed ("Not your turn", "Cell taken",
  "Waiting for Bob", "Pick one of your own pieces", "That move is not allowed", "Go to the latest move to play"),
  and the pressed cell or hand shows the move at once, before the server answers.
- In: "Reconnecting" on every room control while the realtime connection is being restored (`useReconnecting`).
- In: the room page writes where the match stands (`data-cc-phase`, `data-cc-request`) for tests and telemetry.
- Out: the connection banner and the server restart notice (CC-158), sending network failures to that banner
  (until then they are shown under the button with Retry), telemetry (CC-173 to CC-178).

## Acceptance criteria

- [x] A press on any control gives a visible answer within 100 ms (checked by `e2e/match-shell.spec.js`, CC-170).
- [x] A control that cannot act stays focusable, says why on hover, focus and press, and is announced.
- [x] A slow answer shows a spinner and "Sending…" after 150 ms without the button changing width.
- [x] A failure is explained under the button. Retry shows only for connection, timeout and server failures.
- [x] Every button and link carries `data-cc-control` (unit test `pages/controls.test.jsx` walks the main screens).
- [x] Tests cover the change. Coverage gates hold.
- [ ] Docs updated (BACKLOG status, KNOWN_ISSUES, PROGRESS): left to the docs pass, this branch does not edit them.

## Plan / notes

- `Button` keeps its name and props, so every control in the app is one component. `busy` and `disabled` are gone:
  a button with an `action` shows the phases, and `reason` replaces `disabled`. A blocked submit button cancels its
  form, so Enter in a short room code no longer sends it.
- The waiting words and the label share one grid cell, and the hidden one is `aria-hidden`, so the button keeps its
  width and its name is what is on screen.
- `useAction` starts the work in the press itself (no extra tick), so a move is sent in the same event as the click.
  A second press while the first is on its way waits for the first instead of sending twice.
- Reasons for boards come from `playReason(room, { reconnecting })` in `games/roomView.js`. Each board adds its own
  (a taken cell, a move still on its way). Chess also checks whose move the position says it is.
- Chess squares keep `aria-disabled` as before. Offer draw and Resign do not wait for your turn.
