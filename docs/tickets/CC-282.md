## Research (written before any code)

1. **Our code today.** Twelve ad hoc paragraphs say "Loading…" in different words (`ProfilePage` three times,
   `DailyQuests`, `AchievementGrid`, `StreakCard`, `HomePage`, `LeaderboardPage`, `RoomPage`, `MatchShell`'s board
   fallback, `AdminRoute`, `PrivacySettings`). They take one line, so the content pushes the page down when it
   arrives. Some have `aria-busy`, some not. The cold start has its own screen (CC-232) and buttons have the
   400 ms "Sending…" rule (ADR-038, CC-239).
2. **Others.** NN/g "Skeleton Screens 101" (Tankala, 2023-06-04, reviewed 2026-09-02, read 2026-10-19): show
   nothing under about 1 s, a skeleton for full-page loads of 1 to 10 s, a spinner for a single module, a progress
   bar past 10 s; a skeleton that shows only the frame looks broken; shimmer can distract and needs care. Core Web
   Vitals (web.dev, general knowledge, high confidence): CLS under 0.1 is "good".
3. **Best for ClassiCade.** One `Loading` component in two shapes: a block skeleton that reserves the real layout
   of a list or card (rows, medal grid) and an inline line for small parts. It shows nothing for the first 400 ms
   (the same threshold as ADR-038), then a static token tint with one slow opacity pulse that stops under reduced
   motion, `aria-busy` on the region and one polite "Loading" for screen readers. A failure shows the reason and
   Retry; a truly empty result shows CC-259's empty state.

## Why

On a slow phone the page jumps as each part arrives, and the words differ everywhere.

## Scope

- In: the component, every loading paragraph above converted, a CLS check on the list pages.
- Out: the cold start screen (CC-232), button waits (CC-164), the board's lazy chunk beyond using the component.

## Acceptance criteria

- [ ] No content shift when the profile, leaderboard, quests and achievements load (browser check, CLS under 0.1).
- [ ] Nothing shows for loads under 400 ms (unit test with fake timers).
- [ ] Reduced motion: no pulse.
- [ ] Tests cover the change; `npm run lint`, `npm run format:check`, `npm test` pass.
- [ ] Docs updated (BACKLOG, PROGRESS).
