## Why

The new server is complete enough to play; players need a modern, mobile-friendly app on top of it. This ticket lays the
foundation every screen builds on.

## Scope

- In: `apps/web` workspace — React 19.3, Vite 8.3, React Router 8.4 (latest stable); design tokens with light/dark themes;
  global styles with visible focus and reduced-motion support; `lib/` API + socket clients (`AppRequestError` with server
  codes); services context (DI); `SessionProvider` (restore session, guest on demand, signup/login/logout, socket
  reconnect on identity change); `useGames`; app shell (`Layout` with skip link, nav, identity), `Button`, `ErrorBoundary`,
  home page (pitch, catalog, one-click guest play), not-found page; Vite dev proxy for `/api` and `/socket.io`;
  ESLint for React (hooks rules, fast-refresh rule, no `fetch`/socket in components); Vitest `web` project (jsdom).
- Out: room lobby + share links (CC-023), game screens (CC-024), auth/profile pages (CC-025), serving the build from the
  server + CSP (CC-029/CC-030).

## Notes

- Lint caught a broken config import (react-refresh is ESM-only under `require`) and a render-time side effect in a test.
- ESLint 10 tracks JSX usage natively, so no React lint plugin workaround was needed (verified with a probe file).

## Verification

- 654 tests (5 consecutive green runs) incl. 27 web tests (clients, session lifecycle, app flows, error states, a11y skip link).
- Production build: 98 KB gzipped JS.
- Live through the real Vite dev server: page served, `/api/*` proxied to the real server + MongoDB, guest session cookie
  round-trip, and a WebSocket from the dev origin authenticated with the same identity.
